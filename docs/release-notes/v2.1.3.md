## v2.1.3

> Refreshes Claude Code 2.1.112 wire compatibility, hardens cookie login, improves usage reporting, and includes recent streaming, Console, dependency, and channel maintenance fixes.

### English

#### Fixed

- **Claude Code OAuth compatibility.** Claude-account authorization now uses `claude.com`, token exchange and refresh use the `platform.claude.com` JSON endpoint, and token, profile, and usage requests reproduce the corresponding Axios or Claude Code user agents, headers, redirects, HTTP version, body framing, and request-specific timeouts.
- **Claude Code cookie login.** Native cookie exchange and cookie-only re-bootstrap now use a shared Chrome 148 browser profile through the effective proxy, while ordinary model traffic and refresh-token rotation retain their own transport identity.
- **Claude Code usage reporting.** The usage request now matches the 2.1.112 wire shape and its five-second deadline. Extra-usage cents are normalized to major currency units, and the Console displays localized currency, disabled, and unlimited states without hiding other providers' on-demand limits.
- **Aggregated response content type.** A streaming upstream response aggregated for a non-streaming caller now returns JSON content type and no stale content length.
- **Console dependency security.** Vulnerable transitive versions of `@hono/node-server` and `fast-uri` are patched through lockfile overrides.

#### Changed

- **Claude Code client fingerprint.** Stainless metadata tracks the build platform on native targets and retains the captured Node reference on edge. Claude Code 2.1.112 continues to identify as SDK 0.81.0 on Node v22.20.0, with a 24-hour advertised timeout.
- **Native upstream timeout bounds.** The shared read-idle limit increases from 5 minutes to 1 hour, and the non-streaming total limit increases from 10 minutes to 24 hours. Request-specific limits such as the five-second Claude Code usage request still take precedence.
- **Provider route naming.** The Console now clarifies that a provider name is the route segment used in downstream URLs.

#### Removed

- **ChatGPT Web channel.** The deprecated `chatgpt` channel and `channel-chatgpt` feature are removed. Existing persisted ChatGPT providers are disabled during migration.

### 简体中文

#### 修复

- **Claude Code OAuth 兼容性。** Claude 账号授权改用 `claude.com`,Token 交换与刷新改用 `platform.claude.com` JSON Endpoint;Token、Profile 与 Usage 请求分别复刻对应的 Axios 或 Claude Code User-Agent、Header、Redirect、HTTP 版本、Body Framing 与请求级 Timeout。
- **Claude Code Cookie 登录。** Native Cookie Exchange 与仅 Cookie 的重新 Bootstrap 现在通过有效 Proxy 使用共享 Chrome 148 浏览器指纹;普通模型流量与 Refresh Token 轮换继续使用各自的传输身份。
- **Claude Code 用量展示。** Usage 请求对齐 2.1.112 Wire Shape及 5 秒 Deadline。Extra Usage 的分值会换算为主要货币单位,Console 可本地化显示金额、未启用与无限制状态,同时不会隐藏其他 Provider 的按量额度。
- **聚合响应 Content-Type。** 为非流式调用方聚合流式上游响应后,现在会返回 JSON Content-Type并移除失效的 Content-Length。
- **Console 依赖安全。** 通过 Lockfile Override修复 `@hono/node-server` 与 `fast-uri` 的传递依赖漏洞版本。

#### 调整

- **Claude Code 客户端指纹。** Native目标的 Stainless Metadata跟随构建平台,Edge继续使用抓取时的 Node参考平台。Claude Code 2.1.112仍标识为 Node v22.20.0上的 SDK 0.81.0,并声明 24 小时 Timeout。
- **Native 上游超时边界。** 共享读空闲上限从 5 分钟提高到 1 小时,非流式总上限从 10 分钟提高到 24 小时;Claude Code Usage的 5 秒等请求级限制仍优先生效。
- **Provider 路由命名。** Console现在明确说明 Provider Name是下游 URL中使用的路由段。

#### 移除

- **ChatGPT Web Channel。** 移除已弃用的 `chatgpt` Channel与 `channel-chatgpt` Feature;迁移时会停用已有的 ChatGPT Provider。
