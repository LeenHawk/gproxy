## v2.3.0

> Hardens reusable protocol, transform, streaming, and tokenization boundaries for production embedding. This is a breaking Rust-library release; existing GPROXY databases and HTTP clients remain compatible.

### English

#### Added

- **Structured transform diagnostics.** `request_bytes_detailed`, `response_bytes_detailed`, and the detailed stream APIs return the converted value together with structured `LossyField` / `UnsupportedField` diagnostics. The host records these diagnostics instead of relying on tracing-only warnings.
- **Safe wire construction.** Public named protocol structs expose generated builders and the `gproxy_protocol::wire!` helper, allowing construction after the wire models became non-exhaustive.
- **Strict bounded stream decoding.** SSE frame and retained-buffer limits are enforced by every decoder entry point. Channel byte decoders report malformed, truncated, and oversized input through `ClientError::Decode`, and the network pipeline propagates that failure.

#### Changed

- **Non-exhaustive protocol API.** Public provider wire structs and enums are now `#[non_exhaustive]`, so additive provider fields and variants no longer force a major version by themselves.
- **Protected operation keys.** `OperationKey` fields are private and all public construction paths enforce the operation/kind invariant. Endpoint synthesis rejects inconsistent, unsupported, stream-mismatched, or missing-model inputs and encodes raw model ids as one path/query component.
- **Stateful `0..N` streaming.** One stream converter is retained for the full response, and one input frame can emit zero or many output events. Conversion errors and abnormal EOF no longer produce a synthetic successful terminator.
- **Host-owned routing.** Database rule parsing, ordering, and routing policy moved out of `gproxy-transform`; the generic transform crate now contains wire conversion only.
- **Tokenizer diagnostics and features.** Detailed and strict counting expose method, vocabulary, and warnings; malformed JSON is diagnosed, registry rules are deterministic, negative caching avoids repeated misses, downloads are bounded and validated, and local-counting features are split into tiktoken, HF registry, and bundled fallback layers.

#### Migration

- Pin all lockstep crates to `=2.3.0` (`gproxy-protocol`, `gproxy-transform`, and `gproxy-channel-api`).
- Replace `key.operation` / `key.kind` with `key.operation()` / `key.kind()`; construct keys with `content_generation`, `provider`, or `try_new`.
- Replace downstream protocol struct literals with `Type::builder()...build()?` or `gproxy_protocol::wire!(Type { ... })`. Add `_` arms to protocol enum matches.
- Handle `Result` from `SseDecoder::push` / `finish` and `ByteStreamDecoder::push` / `finish`.
- Retain one `StreamConverter` or `SseTransformer` for each response and consume every event in the returned vector.
- Move routing-rule policy into the host. `RoutingDecision` is available from `gproxy-channel-api::routes`; it is no longer exported by `gproxy-transform`.
- Use the detailed transform APIs when semantic loss matters; the legacy value-only transform methods remain as convenience wrappers.

### 简体中文

#### 新增

- **结构化转换诊断。** `request_bytes_detailed`、`response_bytes_detailed` 与详细流式 API 会同时返回转换结果和结构化 `LossyField` / `UnsupportedField` 诊断。宿主会记录这些诊断，不再只依赖 tracing warning。
- **安全的 wire 构造方式。** 公共命名 protocol struct 提供生成的 builder 与 `gproxy_protocol::wire!` helper，可在 wire model 改为 non-exhaustive 后继续安全构造。
- **严格且有界的流解码。** 所有 SSE decoder 入口都会执行 frame 与累计缓冲上限。Channel byte decoder 通过 `ClientError::Decode` 报告坏帧、截断和超限输入，网络 pipeline 会原样传播失败。

#### 调整

- **Non-exhaustive protocol API。** 公共 provider wire struct 与 enum 现统一使用 `#[non_exhaustive]`，今后新增 provider 字段或 variant 不必仅因此提升 major。
- **受保护的 operation key。** `OperationKey` 字段已私有化，所有公共构造入口都会检查 operation/kind 不变量。Endpoint synthesis 会拒绝不一致、不支持、stream 不匹配或缺少 model 的输入，并把裸 model id 编码为单个 path/query component。
- **有状态的 `0..N` 流转换。** 每条响应会持续持有同一个 stream converter，一帧输入可产生零到多个输出事件。转换失败或异常 EOF 不再补出伪成功结束事件。
- **Routing 归宿主所有。** 数据库规则解析、排序和路由策略已移出 `gproxy-transform`；通用 transform crate 只保留 wire conversion。
- **Tokenizer 诊断与 feature。** 详细/严格计数会暴露 method、vocabulary 与 warning；无效 JSON 会产生诊断，registry 规则顺序稳定，negative cache 避免反复 miss，下载具备校验与大小限制，本地计数拆为 tiktoken、HF registry 和 bundled fallback 三层 feature。

#### 迁移

- 将 lockstep crate 精确锁定为 `=2.3.0`（`gproxy-protocol`、`gproxy-transform`、`gproxy-channel-api`）。
- 将 `key.operation` / `key.kind` 改为 `key.operation()` / `key.kind()`；使用 `content_generation`、`provider` 或 `try_new` 构造 key。
- 将下游 protocol struct literal 改为 `Type::builder()...build()?` 或 `gproxy_protocol::wire!(Type { ... })`；匹配 protocol enum 时增加 `_` 分支。
- 处理 `SseDecoder::push` / `finish` 与 `ByteStreamDecoder::push` / `finish` 返回的 `Result`。
- 每条响应持续复用同一个 `StreamConverter` 或 `SseTransformer`，并消费返回 vector 中的全部事件。
- 把 routing rule policy 放到宿主；`RoutingDecision` 从 `gproxy-channel-api::routes` 获取，不再由 `gproxy-transform` 导出。
- 需要关注语义损失时使用 detailed transform API；原 value-only 方法仍作为便利 wrapper 保留。
