# GPROXY 4.0.0

Release notes draft. Version 4.0.0 has not been published yet.

## Highlights

- A shared Rust gateway core for the CLI, Tauri desktop/mobile application, and Cloudflare Workers host.
- An Application first-run wizard for connection settings, administrator credentials, and optional v4 configuration import.
- A unified console for personal and administrative pages, provider credentials, upstream login, model routes, rewrite rules, budgets, and usage.
- Model route names are the names clients request. Members select providers and upstream models, with weights and fallback tiers.
- Rewrite rules include system text, cache breakpoints, JSON edits, text transforms, and headers.
- Usage records describe physical upstream calls, with token/media/tool quantities and attribution independent of capture logs.
- Automatic migration of supported v3 SQLite databases, including accounts, password hashes, key digests, configuration, and historical usage without recalculating old charges.

## Upgrading

Stop v3 and back up the database, master key, and startup configuration. Start v4 with the same paths and key. Migration keeps a backup and reports unsupported mappings. Review the report before returning the instance to service.

See [Migrating v3 to v4](https://gproxy.leenhawk.com/deployment/v3-to-v4/). API payloads, model configuration, and management behavior have changed; check integrations against the v4 documentation.

## Packages and limitations

CLI and Application packages are separate. Platform formats and installation restrictions are listed in [Installation](https://gproxy.leenhawk.com/getting-started/installation/).

Windows MSIX attachments are unsigned Store submission packages. macOS apps use ad-hoc signing and are not notarized. The HarmonyOS HAP is experimental, requires signing, has not been verified on a physical device, and has no background service.

Workers does not support WebSocket / Realtime. Set the `GPROXY_ADMIN_PASSWORD` secret to create the first administrator on an empty database. See [Edge deployment](https://gproxy.leenhawk.com/deployment/edge/).

## 简体中文

本文为发布说明草稿，4.0.0 尚未发布。

### 主要变化

- CLI、Tauri 桌面与移动应用、Cloudflare Workers 共用 Rust 网关核心。
- Application 提供首次设置向导，配置实例连接、管理员账户并可选导入 v4 配置。
- 个人页与管理页统一到一个控制台，管理供应商、凭证、上游登录、模型路由、重写规则、预算和用量。
- 路由名称直接作为客户端模型名，成员配置供应商、上游模型、权重与回退层级。
- 重写规则支持系统提示词、缓存断点、JSON 改写、文本转换和请求头。
- 按实际的上游调用记录用量，token、媒体与工具数量及费用归属不依赖抓包日志。
- 支持自动迁移 v3 SQLite 数据库，保留账户、密码哈希、密钥摘要、配置和历史用量，不重新计算历史费用。

### 升级

停止 v3，备份数据库、主密钥和启动配置，再以相同路径与主密钥启动 v4。迁移保留备份，并报告无法映射的内容；恢复服务前请检查报告。

详见[从 v3 迁移到 v4](https://gproxy.leenhawk.com/zh-cn/deployment/v3-to-v4/)。API 数据结构、模型配置与管理行为已有变化，旧集成需要按 v4 文档核对。

### 安装与限制

CLI 与 Application 独立提供，包格式和平台要求见[安装](https://gproxy.leenhawk.com/zh-cn/getting-started/installation/)。Windows MSIX 是未签名商店提交包；macOS 应用使用 ad-hoc 签名，尚未公证；鸿蒙 HAP 需要签名，尚未真机验证，也不提供后台服务。

Workers 不支持 WebSocket / Realtime；空数据库通过 `GPROXY_ADMIN_PASSWORD` Secret 创建首个管理员，详见[边缘部署](https://gproxy.leenhawk.com/zh-cn/deployment/edge/)。
