## v2.0.16

> Adds a Claude Web channel with live model and usage discovery, introduces proxy connectivity diagnostics, and fixes incomplete terminal output in Codex Responses streams.

### English

#### Added

- **Claude Web channel.** GPROXY can now use a logged-in `claude.ai` browser session as a Claude Messages upstream, including browser-fingerprint emulation, temporary conversation management, attachment uploads, legacy and modern SSE normalization, locally synthesized token usage, and image input handling.
- **Claude Web client tools.** Client-defined tools now complete the full two-request flow: GPROXY ends the first downstream response at `tool_use`, retains the open Claude Web conversation stream, posts the following `tool_result`, and resumes the response through `end_turn` and `message_stop`.
- **Live Claude Web account metadata.** Cookie bootstrap discovers the active organization and model catalogue dynamically, while the credential usage endpoint reports the account's current session and weekly utilization windows.
- **Proxy connectivity tests.** Provider, credential, and instance settings screens can now test an HTTP, HTTPS, SOCKS4, or SOCKS5 proxy against a chosen URL. The admin endpoint reports DNS, TCP, proxy handshake, TLS, HTTP status, timing, and stage-specific failures.

#### Fixed

- **Codex completed output.** Codex Responses streams now retain observed message, reasoning, function-call, and custom-tool items and backfill them into an otherwise empty `response.completed.response.output` array.
- **Multi-step streaming transport.** The upstream capture wrapper now forwards native streaming requests instead of buffering them, preventing Claude Web tool calls from waiting indefinitely for an upstream EOF that only arrives after `tool_result`.
- **Claude Web Cloudflare state.** Full browser Cookie headers and browser device IDs are preserved, Cookie login uses the channel's Edge fingerprint, and its pooled client is reused for subsequent requests so bootstrap response cookies and connection state are not discarded.

#### Changed

- **Protocol crate licensing.** `gproxy-protocol` now uses the MIT license, with the package metadata, bundled license file, and README updated consistently.
- **Claude Web model source.** The channel relies on the model catalogue returned by the authenticated Claude bootstrap response rather than a bundled static model list.

### 简体中文

#### 新增

- **Claude Web 渠道。** GPROXY 现在可以使用已登录 `claude.ai` 的浏览器会话作为 Claude Messages 上游，覆盖浏览器指纹模拟、临时对话管理、附件上传、新旧 SSE 规范化、本地 token usage 合成和图片输入。
- **Claude Web 客户端工具。** 自定义工具现在支持完整的两段请求流程：GPROXY 在第一段 `tool_use` 处结束下游响应并保留 Claude Web 原始对话流，收到下一次 `tool_result` 后提交结果，再继续输出直到 `end_turn` 和 `message_stop`。
- **Claude Web 实时账号信息。** Cookie bootstrap 会动态发现当前 organization 和模型目录；credential usage 端点则返回账号当前的会话与每周用量窗口。
- **代理连通性测试。** Provider、credential 和 instance settings 页面现在可以针对指定 URL 测试 HTTP、HTTPS、SOCKS4 或 SOCKS5 代理。管理端点会报告 DNS、TCP、代理握手、TLS、HTTP 状态、耗时以及具体失败阶段。

#### 修复

- **Codex completed output。** Codex Responses 流现在会保留已出现的 message、reasoning、function call 和 custom tool item，并在 `response.completed.response.output` 为空时补齐这些内容。
- **多步骤流式传输。** Upstream capture 包装器现在会正确转发原生流式请求，不再将其缓冲，避免 Claude Web 工具调用一直等待只有提交 `tool_result` 后才会到来的上游 EOF。
- **Claude Web Cloudflare 状态。** 现在会保留完整浏览器 Cookie header 和浏览器 device ID；Cookie 登录使用渠道自己的 Edge 指纹，并与后续请求复用连接池，避免丢失 bootstrap 返回的 Cookie 与连接状态。

#### 调整

- **Protocol crate 许可证。** `gproxy-protocol` 已切换为 MIT license，并同步更新 package metadata、随包 license 文件和 README。
- **Claude Web 模型来源。** 渠道现在完全使用认证后 Claude bootstrap 响应返回的模型目录，不再携带静态模型列表。
