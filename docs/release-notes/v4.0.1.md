# GPROXY 4.0.1

> Hosted deployment templates, external database options, and administrator password fixes.

## English

### Added

- One-click templates for Netlify Functions, Vercel Functions and Deno Deploy. They download prebuilt Linux executables, use PostgreSQL for persistent state and shared cache, and accept an external database connection.
- An external libSQL/Turso option for Cloudflare Workers. The default Worker package now includes both D1 and libSQL support.
- Linux x86_64 and ARM64 serverless release packages. These templates support HTTP and SSE; WebSocket deployments should use Cloudflare Workers or a native server.

### Fixed

- Strip WASM debug symbols after `worker-build`, preserving the target features needed during compilation.
- Apply an explicitly configured administrator password at startup. A matching username takes priority; otherwise administrator `0` is recovered. Unchanged credentials retain sessions, while password changes invalidate them.
- Remove gateway API keys from the headless example's startup output.
- Keep container build artifacts isolated between branch release runs.

### Changed

- Add GitLab as an update source and clarify release, beta and development publication channels.
- Refresh the README and hosted deployment guide. Templates pin this release; keep the database and encryption key when redeploying.

## 简体中文

### 新增

- Netlify Functions、Vercel Functions 和 Deno Deploy 一键部署模板。模板下载预编译的 Linux 程序，使用 PostgreSQL 保存数据和共享缓存，也可填写外部数据库连接。
- Cloudflare Workers 外部 libSQL/Turso 数据库选项，默认 Worker 包同时包含 D1 与 libSQL 支持。
- Linux x86_64 和 ARM64 serverless 发布包。这三个模板支持 HTTP 和 SSE；需要 WebSocket 时请使用 Cloudflare Workers 或原生服务。

### 修复

- 在 `worker-build` 完成后剥离 WASM 调试符号，保留构建过程中需要的目标特性。
- 启动时应用显式配置的管理员密码。优先匹配用户名；没有匹配用户时恢复管理员 `0`。凭证未变化时保留会话，密码变化时注销旧会话。
- 移除 headless 示例启动输出中的网关 API Key。
- 隔离不同分支发布任务的容器构建产物。

### 调整

- 更新来源新增 GitLab，并明确稳定版、测试版和开发版的发布渠道。
- 更新 README 和托管部署说明。部署模板固定使用此版本；重新部署时保留数据库和加密密钥。
