## v3.0.0-alpha.11

> GPROXY v3 staging: unified account OAuth and guarded native SQLite upgrades.

### English

#### Added

- Channel-independent account OAuth with browser PKCE and device authorization, configurable public clients, and Portal session history, refresh counts and revocation. Codex compatibility remains supported.
- Independent local `pi-gproxy` integration for Pi 0.85.1: GPROXY login, account-scoped model discovery, standard Responses streaming, model refresh and capability-aware priority service.
- Native startup can back up and migrate supported v2 SQLite databases before opening the v3 store. Validation checks import counts, database integrity, references, recoverable secrets and exact settled usage totals before atomic replacement.
- Rolling staging builds from `main`, with signed commit-identified manifests, commit-prefixed assets and retained download targets from the previous manifest.

#### Fixed

- Preserve v2 SQLite DSNs, `--persistence db`, update-channel selection and restart arguments. Reserve the listening port before migration to avoid modifying data when the old server still occupies that port.
- Revocation affects subsequent HTTP requests and WebSocket inference turns; OAuth internal keys cannot bypass the session lifecycle through ordinary API-key management.
- Keep usage records and quota history in separate switchable views.

#### Changed

- `main` now contains the v3 Rust workspace; v2 history remains available in Git and version tags. Staging does not publish crates or the Pi package.
- Automatic migration stops on unmapped populated tables, unsupported policies or unrecoverable secrets rather than silently dropping them. A failure marker prevents repeated backup attempts by supervisors.
- Backups and migration reports remain beside the database. Existing v2 updaters do not retain the old executable: save it before updating, or reinstall the matching official v2 package for rollback. Remote databases require explicit migration; login sessions may require reauthentication.
- Read [the upgrade and rollback guide](https://github.com/LeenHawk/gproxy/blob/main/docs/v2-upgrade.md) before applying staging. Local streaming/tool tests use simulated upstreams; they are not production-provider validation.

### 简体中文

#### 新增

- 跨渠道的账户 OAuth：浏览器 PKCE、设备码授权、可配置客户端，以及 Portal 登录历史、刷新次数和会话撤销；保留 Codex 兼容入口。
- 独立本地 `pi-gproxy` 扩展，适配 Pi 0.85.1，支持 GPROXY 登录、账户可访问模型发现、标准 Responses 流式推理、目录刷新和按能力启用优先服务。
- 原生启动可备份并迁移受支持的 v2 SQLite 数据库；在原子切换前验证导入数量、数据库完整性、引用、可恢复密钥，以及用量数量和精确结算总额。
- `main` 滚动发布 staging，使用签名提交标识清单和带提交前缀的产物，并保留上一份清单引用的下载文件。

#### 修复

- 兼容 v2 的 SQLite DSN、`--persistence db`、更新渠道和重启参数；迁移前先占用监听端口，避免旧实例仍占用该端口时修改数据库。
- 撤销对后续 HTTP 请求及 WebSocket 新推理轮次生效；内部 OAuth 密钥不能通过普通 API Key 管理绕过会话生命周期。
- 用量列表和配额历史使用独立的可切换视图。

#### 变更

- `main` 切换到 v3 Rust 工作区，v2 历史保留在 Git 和版本标签中；staging 不发布 crates 或 Pi npm 包。
- 遇到未覆盖的非空数据表、无法表达的策略或不可恢复密钥时，自动迁移停止，不静默丢弃数据；失败标记阻止进程管理器反复生成备份。
- 数据库旁保留备份和迁移报告。现有 v2 更新器不会保留旧程序，请升级前自行保存，或回滚时重装对应的官方 v2 包。远程数据库需显式迁移，登录会话可能需要重新认证。
- 应用 staging 前请阅读[升级与回滚指南](https://github.com/LeenHawk/gproxy/blob/main/docs/v2-upgrade.md)。本地流式和工具多轮测试使用模拟上游，不代表真实生产供应商验证。
