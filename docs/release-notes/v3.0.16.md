## v3.0.16

> Correct provider-scoped model catalogues and model names.
> 修复渠道限定路由的模型列表范围和模型名称。

### English

#### Fixed

- Requests such as `/provider/v1/models` now return only that provider's models, without the gateway-added `provider/` prefix. Upstream model IDs such as `vendor/model` retain their own prefix. This applies to OpenAI, Claude, Gemini, and Codex model-list formats and provider model lookups.
- Provider-scoped catalogues include the enabled, manually maintained models when automatic refresh is disabled, preserving their configured metadata and model permissions. Explicit discovery and credential-local catalogues continue to use the current upstream or credential's models.
- Preserve namespace and named-route precedence when a path prefix also matches a provider name.

### 简体中文

#### 修复

- `/provider/v1/models` 等渠道限定入口只返回该渠道的模型，并去掉网关添加的 `provider/` 前缀；上游模型自身的 `vendor/model` 前缀保持完整。覆盖 OpenAI、Claude、Gemini、Codex 模型列表格式及渠道模型详情查询。
- 关闭自动刷新时，渠道限定列表仍包含手工维护且已启用的模型，并保留配置的模型元数据和权限过滤。显式发现模型及凭证本地目录继续以当前上游或凭证提供的模型为准。
- 当前缀同时匹配渠道名称与命名空间或路由名称时，保留原有的命名空间、路由优先级。
