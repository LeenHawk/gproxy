## v2.0.18

> Adds secure first-run administrator setup and login-startup choices to native installers, improves Android background startup onboarding, and makes the GitHub Release publishing path reliable under repository integration restrictions.

### English

#### Added

- **Desktop first-run setup.** Windows MSI, macOS DMG, and Linux DEB installations now ask for an administrator username and non-blank password before the first server start. The launchers retain only the username; the password is passed to that start without being written to disk.
- **Installer startup choice.** MSI, DMG, and DEB setup now asks whether GPROXY should start automatically when the user signs in. The selected Windows Startup, macOS LaunchAgent, or Linux XDG preference remains compatible with the Background Service setting in Console.
- **Android background onboarding.** The APK keeps its app-launch and device-boot startup switch, requires administrator credentials before the first start, and guides users through Android's battery-optimization exemption when background startup is enabled. Existing APK installations migrate without losing their configured startup state.

#### Fixed

- **Release publishing permissions.** The local release command now creates the required draft with the maintainer's authenticated identity, allowing GitHub Actions to upload assets and publish it without the previous `Resource not accessible by integration` failure.
- **Installer secret handling.** Native launchers avoid persisting administrator passwords in startup entries or configuration files and mark setup-managed startup state so the core does not overwrite the user's first-run choice.
- **Release archive licensing.** Portable native archives now consistently include `LICENSE`, including Windows ZIP artifacts.

#### Changed

- **Quick Start without a starter bundle.** The English and Chinese guides now teach users to choose administrator credentials, sign in to Console, create a provider and credential, configure a route, and generate a user API key. The old starter Bundle download and placeholder-key flow has been removed.
- **Project presentation.** The READMEs now use the requested Star History chart, retain GitHub Sponsors links, and direct regular users to the categorized download page and latest GitHub Release.

### 简体中文

#### 新增

- **桌面端首次设置。** Windows MSI、macOS DMG 和 Linux DEB 现在会在服务器首次启动前要求设置管理员用户名和非空密码。Launcher 只保留用户名，密码仅传给本次启动，不会写入磁盘。
- **安装器自动启动选项。** MSI、DMG 和 DEB 首次设置时都会询问是否随用户登录自动启动 GPROXY。对应的 Windows Startup、macOS LaunchAgent 或 Linux XDG 选择仍可通过 Console 的后台运行设置继续修改。
- **Android 后台运行引导。** APK 保留打开 App 与设备开机后的自动启动开关，首次启动前必须设置管理员凭据；开启后台自启时会引导用户允许 Android 电池优化豁免。已有 APK 安装会迁移原有配置，不会丢失启动状态。

#### 修复

- **Release 发布权限。** 本地发布命令现在会使用维护者已认证身份预先创建所需草稿，使 GitHub Actions 可以上传产物并发布，不再触发 `Resource not accessible by integration`。
- **安装器敏感信息处理。** 原生 launcher 不会把管理员密码写入启动项或配置文件，并会标记由首次设置管理的启动状态，避免核心程序覆盖用户的选择。
- **Release 归档许可证。** 便携 native 压缩包现在会一致包含 `LICENSE`，包括 Windows ZIP 产物。

#### 调整

- **不再依赖初始 Bundle 的快速开始。** 中英文指南现在引导用户设置管理员凭据、登录 Console、创建 Provider 与 credential、配置 Route，并生成 user API key；旧的 starter Bundle 下载和占位 key 流程已删除。
- **项目展示。** README 已换成指定的 Star History 图表，保留 GitHub Sponsors 链接，并继续优先引导普通用户前往分类下载页和最新 GitHub Release。
