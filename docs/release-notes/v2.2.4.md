## v2.2.4

> Corrects AWS Bedrock streaming usage accounting and preserves native cache and thinking-token semantics across transformed protocols.

### English

#### Fixed

- **AWS Bedrock usage settlement.** ConverseStream now records the input and cache fields delivered alongside output usage in Bedrock's final metadata instead of retaining placeholder input values. Bedrock cache details are mapped to Claude's 5-minute and 1-hour creation buckets, and supported Claude cache TTLs are forwarded to Converse `cachePoint`. Missing or incomplete usage now falls through to token counting while explicit complete zero usage remains authoritative; settlement also tolerates metadata before `messageStop` and shapes CountTokens requests to the fields accepted by Bedrock.
- **Transformed usage semantics.** Usage conversion among OpenAI, Claude, and Gemini now follows the destination protocol's native definitions: Claude input excludes cache tokens, OpenAI input totals include them, and Gemini candidate tokens exclude separately reported thinking tokens. This prevents cache or thinking tokens from being duplicated, omitted, or under-reported in cross-protocol responses, and compact-response settlement preserves the target protocol's cache-TTL breakdown before response conversion.

### 简体中文

#### 修复

- **AWS Bedrock 用量结算。** ConverseStream 现会记录 Bedrock 最终 metadata 中与输出用量一同提供的输入及缓存字段，不再保留占位输入值。Bedrock cache detail 会映射到 Claude 的 5 分钟与 1 小时缓存创建分项，支持的 Claude cache TTL 也会转发到 Converse `cachePoint`。缺失或不完整的 usage 现会进入 Token 计数回退，同时完整且明确的零用量仍视为有效；结算也可处理先于 `messageStop` 到达的 metadata，并将 CountTokens 请求限制为 Bedrock 接受的字段。
- **跨协议转换用量语义。** OpenAI、Claude 与 Gemini 之间的 usage 转换现遵循目标协议的原生定义：Claude 输入不含缓存 Token，OpenAI 输入总量包含缓存 Token，Gemini candidate Token 不包含另行报告的 thinking Token。这可避免跨协议响应中的缓存或 thinking Token 被重复计算、遗漏或少计；compact response 结算也会在响应转换前保留目标协议的缓存 TTL 分项。
