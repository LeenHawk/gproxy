## v2.0.19

> Restores the gproxy v1 Claude Code client fingerprint and literal billing checksum, makes provider model refresh policy configurable and routing-aware, adds administrator update notifications, and refreshes the supported dependency and CI toolchain.

### English

#### Added

- **Administrator update banner.** The admin Console checks for an update when it opens and shows a quiet banner only when a newer build is available, linking directly to the Updates page. Tagged builds default to the stable update channel while rolling main builds default to staging, unless the operator overrides the channel.
- **Provider model refresh control.** Provider settings now expose an `auto_refresh_models` switch. Automatic model discovery remains enabled by default and can be disabled when operators want the persisted catalogue to remain authoritative.

#### Fixed

- **Claude Code v1 fingerprint compatibility.** Claude Code traffic now matches the gproxy v1.0.22 / Claude Code 2.1.112 identity: `claude-cli/2.1.112 (external, cli)`, Anthropic SDK 0.81.0 on Node v22.20.0, the v1 request headers, random persisted device ids, and random process-style session UUIDs reused for 20 minutes. OAuth profile and cookie bootstrap requests use their corresponding v1 user-agent shapes, while model calls continue to carry `?beta=true`.
- **Claude Code billing attribution.** The billing block now uses `cc_version=2.1.112.*`, `cc_entrypoint=cli`, and sends the literal `cch=00000` accepted by the v1 client path. The newer XXH64 post-serialization rewrite and its direct dependency have been removed.
- **Routing-aware model catalogues.** Aggregated and scoped model listings now apply the same provider refresh policy: disabled refresh or a `local` ListModels rule serves persisted models without upstream traffic, while eligible providers refresh concurrently and keep additive persistence and permission filtering.

#### Changed

- **Dependency and CI refresh.** Backend crypto, persistence, HTTP, archive, and WebAssembly dependencies were updated together with Console, documentation, Node setup, Docker build, and GitHub Actions tooling.

### 简体中文

#### 新增

- **管理员更新提示。** 管理员 Console 打开时会检查一次更新，仅在发现更高版本时显示安静的提示条，并可直接进入更新页面。Tag 构建默认跟踪稳定发布通道，main 分支滚动构建默认跟踪 staging；管理员仍可显式覆盖更新通道。
- **Provider 模型刷新开关。** Provider 设置新增 `auto_refresh_models` 开关。自动发现模型默认保持开启；需要让持久化模型目录作为唯一权威来源时可以关闭。

#### 修复

- **Claude Code v1 指纹兼容。** Claude Code 流量现在对齐 gproxy v1.0.22 / Claude Code 2.1.112：使用 `claude-cli/2.1.112 (external, cli)`、Anthropic SDK 0.81.0、Node v22.20.0、v1 请求 header、随机持久化 device id，以及按 CLI 进程风格生成并复用 20 分钟的随机 session UUID。OAuth profile 与 cookie bootstrap 请求分别使用对应的 v1 User-Agent；模型请求继续携带 `?beta=true`。
- **Claude Code billing attribution。** Billing block 现在使用 `cc_version=2.1.112.*`、`cc_entrypoint=cli`，并直接发送 v1 客户端路径接受的字面量 `cch=00000`。已移除新版 XXH64 序列化后重写逻辑及其直接依赖。
- **路由感知的模型目录。** 聚合与 scoped 模型列表现在使用同一套 Provider 刷新策略：关闭自动刷新或 ListModels 路由为 `local` 时直接读取持久化模型且不访问上游；符合条件的 Provider 仍会并发刷新，并保持增量持久化和权限过滤。

#### 调整

- **依赖与 CI 工具链更新。** 后端加密、持久化、HTTP、归档与 WebAssembly 依赖已更新，Console、文档、Node setup、Docker 构建和 GitHub Actions 工具链也同步升级。
