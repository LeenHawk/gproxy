---
title: 從 v3 遷移到 v4
description: 使用原配置啟動 v4，自動遷移 SQLite、PostgreSQL、MySQL 和 D1 中的 v3 資料。
---

**替換二進位制，按原來的配置啟動即可。** v4 會識別已有的 v3 資料庫並自動遷移，支援 SQLite、PostgreSQL、MySQL 和 D1。
繼續使用原資料目錄、資料庫路徑和 `GPROXY_MASTER_KEY`，不需要匯出、新建目錄或
重設密碼。原使用者名稱、密碼和 API key 保持可用。

## SQLite 檔案遷移

繫結 HTTP 連接埠前，v4 先生成完整 SQLite 快照，包括已提交的 WAL 內容，再在原庫旁的
臨時資料庫中完成轉換。使用已有主金鑰解密憑證，保留使用者的 Argon2 密碼雜湊。只有
匯入和執行快照裝配全部成功，才替換原資料庫路徑，並在旁邊保留
`gproxy.db.v3-*.bak` 備份，日誌會輸出備份位置。

轉換失敗不會替換原庫。修正實際錯誤（例如恢復原有主金鑰）後重啟即可。替換前中斷，
原路徑仍然是 v3；替換後啟動，透過 v4 的遷移賬本識別為已完成，不會重複匯入。

與其他 schema 遷移一樣，升級期間保持單寫者：停止 v3 後再啟動 v4。即使資料庫已經
分開，也不要讓兩套部署同時使用同一份 OAuth 憑證，以免 refresh token 輪換互相影響。

## PostgreSQL、MySQL 與 D1

繼續使用原連線地址或 D1 binding，以及原有主金鑰，不需要手動匯出或建立新資料庫。CLI 的 PostgreSQL / MySQL 部署需使用包含對應驅動的構建。

遷移先檢查源資料和憑證主金鑰，再將原表改名為 `gproxy_v3_<原表名>`。原資料保留在這些歸檔表中；新 v4 表使用原來的名稱。遷移會逐步建立新表，轉換配置、身份和歷史用量，校驗執行配置後才允許服務流量。

- **PostgreSQL**：用資料庫會話鎖序列執行遷移，舊錶改名在同一事務中完成。
- **MySQL**：會話鎖覆蓋 DDL 隱式提交，使用一次 `RENAME TABLE` 改名舊錶。
- **D1**：改名使用事務性 batch；遷移租約與每批寫入的持有者檢查防止多個 isolate 同時修改資料。中斷後租約最多 60 秒釋放。

進度記錄在 `gproxy_v3_upgrade`。 其中的 `report_json` 儲存跳過項和語義變化警告。身份資料和歷史用量分批提交併儲存遊標；異常退出後，下次啟動或 Worker 請求會繼續未完成的遷移。遷移期間不會建立新的初始管理員，也不會開放半完成的實例。

遠端庫遷移失敗時，舊錶仍在歸檔名稱下，新表可能包含已完成的部分。修復實際錯誤並重新啟動即可續跑；不要刪除進度表或改名歸檔表。需要回退到 v3 時，停止所有實例並從升級前備份恢復，不能直接讓 v3 使用部分遷移後的庫。確認升級結果之前請保留歸檔表。

## 資料如何處理

| 資料 | 結果 |
| --- | --- |
| Provider 與憑證 | 轉換已知渠道名稱和配置，按當前主金鑰重新封裝憑證。 |
| 模型路由與成員 | 原公開名稱合入路由名稱；額外名稱展開為獨立路由並複製成員。 |
| 使用者、密碼、API key、組織與團隊 | 保留密碼雜湊和金鑰認證摘要。 |
| 價格與預算 | 轉為 v4 單位；超過 9 位小數時複用 Store 的最近偶數舍入，並報告變化。 |
| 權限、限流與改寫 | 遷移支援的表達形式，報告語義變化和未能對映的內容。 |
| 歷史用量（資料庫遷移） | 分批匯入原 token 數、歸屬和已結算費用，不重新計價或結算配額；額外舊欄位儲存在 `metrics.v3`。 |
| 抓包、請求日誌、會話與審計歷史 | 保留在 v3 備份中；原瀏覽器會話需要重新登入。 |

團隊和組織權限會展開為每位已遷移成員的使用者規則，包括停用使用者。報告逐條列出展開後的規則；沒有已遷移成員的群組會明確記錄為略過。這些規則使用遷移時的成員關係，後續成員變動不會自動更新規則。此修復適用於新的 v3 匯入，不會自動恢復已完成升級時遺失的權限。

沒有可轉換渠道或配置的 Provider 會連同其關聯行一併跳過，並在報告中列明。
這不包括忽略資料庫讀寫錯誤或錯誤的解密金鑰。啟動後檢視報告中的渠道遺漏和權限變化。

`gproxy migrate` 也使用相同的自動升級路徑。升級完成後由 SeaORM 的
`seaql_migrations` 賬本管理 v4 schema 變更。`migrate --status` 只查詢狀態，不執行
v3 升級。

## 可選：另行匯入備份或匯出檔案

如果確實要匯入另一份實例，仍可顯式執行：

```sh
gproxy --data-dir ./other-instance migrate
gproxy --data-dir ./other-instance import --from-v3 /path/to/v3-backup.db
```

這個顯式命令讀取加密源時，透過 `--source-master-key` 或
`GPROXY_IMPORT_SOURCE_MASTER_KEY` 提供源主金鑰。目標必須為空，或只包含先前未完成
的同一匯入。加 `--skip-unmappable-providers` 使用與自動啟動相同的跳過策略。

也支援 v3 的 `POST /admin/api/export` JSON，匯出時使用
`{"include_secrets": true}`。與直接讀取 SQLite 不同，這種匯出缺少密碼雜湊、權限、
限流和 Provider 模型。匯入沒有雜湊的 JSON 時可用 `--admin-password` 設定控制台
密碼；直接遷移 SQLite 不需要它。
