權限決定能訪問什麼，限流決定單位時間能發多少請求，費用預算決定還能花多少錢。這三類設定分別檢查，不能互相替代。

## 權限

權限規則屬於使用者或單把 API Key，並可限定供應商、模型模式和操作。模型模式支援 `*` 與 `?`，因此可以直接限制模型，不需要為每個模型另建供應商。

匹配規則按優先順序從高到低、同優先順序按 ID 排序，使用第一條匹配規則的 `allow` 或 `deny`。普通使用者沒有匹配的允許規則時不能訪問。實例管理員繞過普通權限規則；OAuth 存取權杖仍受固定操作基線限制（模型目錄、token 計數、生成、串流、壓縮），除非用戶端列在 `oauth.cli_client_ids` 中。用戶端請求的 `scope` 只記錄在授權上，不會擴大或縮小這條基線。

| API 欄位 | 含義 |
| --- | --- |
| `userId` / `apiKeyId` | 二選一，指定規則主體 |
| `providerId` | 可選，省略時匹配所有供應商 |
| `modelPattern` | 模型模式，預設 `*` |
| `operation` | 可選，省略時匹配所有操作 |
| `action` | `allow` 或 `deny` |
| `priority` | 數值越大越先匹配 |

模型目錄中的 `permitted` 顯示當前呼叫方是否獲准使用。未獲準的模型仍可能顯示在目錄裡。

## 憑證可見範圍

有模型權限還需要至少一份可用憑證。憑證的使用者、組織和團隊歸屬決定誰能使用它；API Key 的繫結參與這個檢查。不要把管理範圍、模型權限和憑證歸屬當成同一個設定。

供應商服務路由（渠道宣告的帳戶、用量等非模型端點）沒有模型和操作，只有覆蓋整個供應商的規則（任意模型、不限操作）才能允許或拒絕它們。它們不在 OAuth 操作基線內。

## 請求限流

限流規則屬於使用者或 API Key，可配置指標、上限、週期秒數、模型模式和啟用狀態。常用指標是請求數（`requests`）與併發數（`concurrency`）。實時計數由快取後端維護，多實例部署需要共享快取。

權限檢查在限流計數之前執行。被拒絕時檢視返回的錯誤與日誌，區分呼叫方限流和上游憑證限額。

## 費用預算

費用預算可以設定在使用者、API Key、組織和團隊上，以 USD 金額計。請求會檢查金鑰及使用者的預算，以及金鑰實際繫結的組織、團隊預算；不會僅因為團隊屬於某組織就自動給未繫結的組織記賬。

同一請求適用的每條啟用預算都必須有餘量。可以按週期和模型範圍配置，具體選項見控制台。實際費用在上游呼叫結束後結算，因此在途請求和併發呼叫可能使最終費用超過上限，預算不是上游消費的硬性封頂。

價格缺失會影響費用統計和預算消耗，請同時檢查[價格配置](/zh-tw/reference/pricing/)。預算金額透過 API 以十進位制字串傳輸。

## 供應商與憑證限額

供應商預設限額分別作用於每份憑證，不是所有憑證共用一個池。憑證的同名啟用規則覆蓋供應商預設規則；恢復繼承會刪除單獨配置。

本地限額與上游帳號額度也不同：重置本地規則不會重置上游餘額或額度視窗。詳見[供應商與憑證](/zh-tw/guides/providers/)和[控制台](/zh-tw/guides/console/)。

## 排查拒絕

- `401`：先檢查金鑰和使用者是否有效。
- `403`：檢查權限、憑證可見範圍及 OAuth 操作基線。
- `429`：檢查呼叫方限流、費用預算、憑證本地限額與上游額度。

先在控制台檢視對應使用者、金鑰和憑證，再根據日誌中的具體錯誤定位限制來源。
