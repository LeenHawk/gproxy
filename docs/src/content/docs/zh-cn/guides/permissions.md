权限、限流和成本配额都挂在一个 **主体** 上：组织、团队、用户或单把 API 密钥。
请求会对照其链路上的每一行进行评估：

```text
api key -> user -> team -> organization
```

控制台中任一层级的 **访问** 卡片会同时显示该层级设置的行以及从上级继承的行，
后者标注为“继承自 …”。

## 权限

一条权限行指定主体、Provider（或全部 Provider）、操作组（或全部操作）以及
效果：允许或拒绝。

评估按解析出的计划中的每个目标 Provider 进行。链路上所有匹配该 Provider 和
操作组的行都会生效。任一匹配的拒绝会拒绝请求；没有任何匹配的允许时同样拒绝。
不存在隐式访问。

操作组：`models`、`count_tokens`、`memories`、`generate_content`、`compact`、
`embeddings`、`images`、`audio`、`video`、`files`、`search`、`rerank`、
`realtime`。

权限按 Provider 和操作组授予，而不是按模型名。若要把某个用户限制在部分模型
上，请把这些模型放到独立的 Provider 中，或通过专用的路由加 Provider 组合公开
它们。门户的 **获准使用的模型** 列表来自同一套检查：模型只会以用户可调用的
能力出现。

:::note
列出模型和统计 Token 属于 `models` 和 `count_tokens` 操作。只拥有
`generate_content` 的用户无法列出模型。
:::

## 限流

一条限流行是主体、请求数和以秒计的窗口。每个（主体，窗口长度）一行；同一
主体可以并存多个窗口。

窗口固定并按 Unix 纪元对齐。计数器位于缓存后端，先自增再判断，因此并发请求
的计数是确定的。被拒绝的请求会回滚其自增，不消耗窗口。链路上每一条匹配的行
都会检查，第一条超限的行拒绝请求。

单凭证的每分钟请求数和每分钟 Token 数保护的是上游账号，在凭证上配置，见
[Provider 与凭证](/zh-cn/guides/providers/)。

## 成本配额

每个主体一条配额行，包含 **总** 限额和可选的窗口限额：

| 窗口 | 重置时间 |
| --- | --- |
| 总计 | 永不重置。 |
| 每日 | UTC 00:00。 |
| 每周 | 周一 UTC 00:00。 |
| 每月 | 每月 1 日 UTC 00:00。 |
| 5 小时 | 首个获准请求后五小时；之后的下一个请求开启新窗口。 |
| 7 天 | 首个获准请求后七天，规则同上。 |

限额是以计价货币计的十进制成本。配额可以禁用而不删除。

### 准入

对每个计费操作，准入会：

1. 以任一候选目标对请求输入 Token（用分词器阶梯统计）可能收取的最高价格
   作为估算成本；
2. 把估算值加到缓存中每个适用配额窗口的待结算计数器；
3. 若窗口已达上限，或已结算成本加待结算值将超过上限，则拒绝；
4. 以请求 id 记录该预留。

请求结束时，已结算成本写入窗口（每个请求 id 只写一次，重试不会重复扣费），
待结算估算值被释放。列出模型、统计 Token 等免费操作跳过配额检查，但仍记录
一次零成本结算。

成本来自[价格与分层](/zh-cn/reference/pricing/)中描述的价格规则。没有匹配
规则的请求照常运行，并以零成本记录用量。

## 被拒绝的请求

所有拒绝都是一个 JSON 错误信封：

```json
{ "error": { "message": "quota exceeded" } }
```

| 状态码 | 消息 | 原因 |
| --- | --- | --- |
| `401` | `unauthorized` | 密钥缺失、未知、已禁用或已过期。 |
| `403` | `forbidden: permission denied` | 链路上没有允许，或存在拒绝。 |
| `429` | `rate limited` | 调用方限流，或凭证 RPM/TPM 上限。 |
| `402` | `quota exceeded` | 某个成本窗口将被超出。 |
| `404` | `unknown route or model: ...` | 模型名解析不到任何目标。 |

## 查看窗口

控制台的 **用量** 页列出每个活跃的配额窗口，并以进度条显示：已结算成本对
上限、百分比、窗口开始时间和重置时间。进度条在 85% 变为警告，100% 变为严重。
尚未收到请求的 5 小时或 7 天锚定窗口显示“未开始”。门户为登录用户的链路显示
同样的进度条，并标注作用域。

## 上游配额周期

`codex`、`claudecode` 和 `geminicli` 上的凭证会报告上游账号自身的限流窗口。
GPROXY 按凭证和窗口键把它们记录为 **配额周期**，含边界来源（上游、推断或
未知）和已用百分比，并显示在凭证卡片上。它们描述的是上游账号而不是你的用户，
与本页的配额相互独立。但它们会影响均衡：在同一故障转移层级内，任一有效窗口
达到 90% 及以上的凭证排在其他凭证之后，达到 100% 的排在最后。没有凭证会因
此从计划中移除。
