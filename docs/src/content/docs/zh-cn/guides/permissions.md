权限决定能访问什么，限流决定单位时间能发多少请求，费用预算决定还能花多少钱。这三类设置分别检查，不能互相替代。

## 权限

权限规则属于用户或单把 API Key，并可限定供应商、模型模式和操作。模型模式支持 `*` 与 `?`，因此可以直接限制模型，不需要为每个模型另建供应商。

匹配规则按优先级从高到低、同优先级按 ID 排序，使用第一条匹配规则的 `allow` 或 `deny`。普通用户没有匹配的允许规则时不能访问。实例管理员绕过普通权限规则；OAuth 访问令牌仍受固定操作基线限制（模型目录、token 计数、生成、流式、压缩），除非客户端列在 `oauth.cli_client_ids` 中。客户端请求的 `scope` 只记录在授权上，不会扩大或缩小这条基线。

| API 字段 | 含义 |
| --- | --- |
| `userId` / `apiKeyId` | 二选一，指定规则主体 |
| `providerId` | 可选，省略时匹配所有供应商 |
| `modelPattern` | 模型模式，默认 `*` |
| `operation` | 可选，省略时匹配所有操作 |
| `action` | `allow` 或 `deny` |
| `priority` | 数值越大越先匹配 |

模型目录中的 `permitted` 显示当前调用方是否获准使用。未获准的模型仍可能显示在目录里。

## 凭证可见范围

有模型权限还需要至少一份可用凭证。凭证的用户、组织和团队归属决定谁能使用它；API Key 的绑定参与这个检查。不要把管理范围、模型权限和凭证归属当成同一个设置。

供应商服务路由（渠道声明的账户、用量等非模型端点）没有模型和操作，只有覆盖整个供应商的规则（任意模型、不限操作）才能允许或拒绝它们。它们不在 OAuth 操作基线内。

## 请求限流

限流规则属于用户或 API Key，可配置指标、上限、周期秒数、模型模式和启用状态。常用指标是请求数（`requests`）与并发数（`concurrency`）。实时计数由缓存后端维护，多实例部署需要共享缓存。

权限检查在限流计数之前执行。被拒绝时查看返回的错误与日志，区分调用方限流和上游凭证限额。

## 费用预算

费用预算可以设置在用户、API Key、组织和团队上，以 USD 金额计。请求会检查密钥及用户的预算，以及密钥实际绑定的组织、团队预算；不会仅因为团队属于某组织就自动给未绑定的组织记账。

同一请求适用的每条启用预算都必须有余量。可以按周期和模型范围配置，具体选项见控制台。实际费用在上游调用结束后结算，因此在途请求和并发调用可能使最终费用超过上限，预算不是上游消费的硬性封顶。

价格缺失会影响费用统计和预算消耗，请同时检查[价格配置](/zh-cn/reference/pricing/)。预算金额通过 API 以十进制字符串传输。

## 供应商与凭证限额

供应商默认限额分别作用于每份凭证，不是所有凭证共用一个池。凭证的同名启用规则覆盖供应商默认规则；恢复继承会删除单独配置。

本地限额与上游账号额度也不同：重置本地规则不会重置上游余额或额度窗口。详见[供应商与凭证](/zh-cn/guides/providers/)和[控制台](/zh-cn/guides/console/)。

## 排查拒绝

- `401`：先检查密钥和用户是否有效。
- `403`：检查权限、凭证可见范围及 OAuth 操作基线。
- `429`：检查调用方限流、费用预算、凭证本地限额与上游额度。

先在控制台查看对应用户、密钥和凭证，再根据日志中的具体错误定位限制来源。
