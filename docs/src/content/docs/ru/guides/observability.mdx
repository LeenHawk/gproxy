Консоль разделяет использование, запросы клиентов, вызовы провайдеров и записи аудита. Они показывают стоимость, клиентский трафик, фактические попытки провайдера и изменения конфигурации соответственно.

<a id="usage-and-costs"></a>

## Использование и затраты

Запись использования представляет собой один физический вызов провайдера. Повторные попытки или отработка отказа могут создавать несколько записей для одного клиентского запроса. Атрибуция учётных данных провайдера и аутентификации, токены, количество носителей/инструментов и стоимость хранятся независимо от журналов захвата.

Поле отсутствующего токена может быть `null`, а не нулевым. `completeness` описывает полноту использования, а `metrics` сохраняет динамические измерения и детали протокола. Затраты зависят от настроенных правил ценообразования, а не от баланса учётной записи провайдера.

Агрегаты можно фильтровать по времени, модели, провайдеру, учётным данным аутентификации и другим параметрам. Проверьте `scanned` и `truncated`: усеченное сканирование не является полным счетом.

<a id="request-logs"></a>

## Запросить журналы

- **Журналы клиентов** описывают запросы клиента к шлюзу.
- **журналы провайдера** описывают физические вызовы провайдера. Один клиентский запрос может иметь несколько попыток.
- **Захваты** сохраняют выбранные запросы, ответы или события потока с учетом настроек сохранения тела.

HTTP/SSE и трафик WebSocket имеют соответствующие записи. Кадры WebSocket — это события соединения; подсчет кадров не обязательно является подсчетом вызовов модели.

<a id="enable-body-recording"></a>

## Включить запись тела

Настройки ведения журнала экземпляра управляют журналами и телами провайдера и клиента отдельно. Например:

```sh
curl -sS -X PATCH http://127.0.0.1:8787/admin/api/settings \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"logging":{"enableUpstreamLogBody":true}}'
```

Запись тела увеличивает накладные расходы на хранение и обработку. В состояниях журнала различают незахваченное, усеченное и полное содержимое. Отсутствие тела не означает, что запрос не был отправлен. Отключение захвата не отключает расчет использования.

Редактирование по умолчанию маскирует распознанные поля секрета, файлов cookie и токена, но не идентифицирует всю личную или деловую информацию в теле. `disableLogRedaction` отключает редактирование журнала; настройте его в соответствии с вашими потребностями.

<a id="query-apis"></a>

## API запросов

Конечные точки управления CLI/контейнера HTTP включают в себя:

| Путь | Содержание |
| --- | --- |
| `/admin/api/usage` | Сводка использования, группы и тенденции |
| `/admin/api/usage/records` | Записи об использовании вызовов для каждого провайдера |
| `/admin/api/logs/downstream` | список запросов клиентов |
| `/admin/api/logs/upstream` | список вызовов провайдера |
| `/admin/api/logs/downstream/{id}` | детали запроса клиента |
| `/admin/api/logs/captures/{id}` | Захватить детали |
| `/admin/api/audit` | Аудиторские записи |

Каждая конечная точка обеспечивает область и возможности управления. Персональные конечные точки `/portal/api/usage`, `/portal/api/quota` и `/portal/api/requests` ограничивают результаты данными, видимыми клиентом API. Приложение выполняет запросы через IPC внутри приложения и не предоставляет эти конечные точки управления через HTTP.

<a id="audit"></a>

## Аудит

Записи аудита охватывают действия руководства и OAuth, включая субъекта, действие, результат и время. `GPROXY_AUDIT_ENABLED=false` отключает новые записи аудита, сохраняя при этом возможность запроса истории. Он не отключает журналы запросов или расчет использования.

<a id="process-logs"></a>

## Журналы процессов

CLI использует `GPROXY_LOG_FILTER` и `GPROXY_LOG_FORMAT` для уровня и формата журнала и записывает журналы процессов в stderr. Первоначально сгенерированные учётные данные администратора передаются на стандартный вывод. Менеджеры сервисов и контейнеры могут собирать оба потока, поэтому защитите первый журнал запуска.

См. [Цены](/ru/reference/pricing/) для правил затрат и [Разрешения, лимиты запросов и бюджеты](/ru/guides/permissions/) для бюджетов.
