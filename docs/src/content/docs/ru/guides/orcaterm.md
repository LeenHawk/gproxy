Канал `orcaterm` использует протокол LightAI из OrcaTerm 1.6.6. Он поддерживает системные инструкции, историю диалога, потоковые ответы и рассуждения. GPROXY предоставляет OpenAI Chat Completions и использует существующие преобразования для Responses, Claude Messages и Gemini.

## Настройка

1. Создайте провайдера **OrcaTerm**. Для китайского сервиса оставьте базовый адрес пустым. Для международной учётной записи включите `international`.
2. Выберите **авторизацию устройства** — способ входа по умолчанию — и откройте ссылку авторизации. Завершите вход в браузере. GPROXY автоматически опрашивает сервис и сохраняет учётные данные OAuth; копировать код устройства, Cookie или URL обратного вызова не нужно. В Китае по умолчанию используется WeChat, в международном сервисе — Google. Параметр `oauth_provider` позволяет выбрать `wechat`, `txcloud` (Tencent Cloud), `google` или `github`; доступность определяется OrcaTerm для выбранного региона.
3. Обновите каталог моделей провайдера. Он загружается из динамической конфигурации Rainbow, используемой настольным клиентом. Сохраняйте полные идентификаторы моделей, включая префиксы `TokenHub/` и `Hunyuan3/`.
4. Назначьте права доступа к импортированным моделям и отправляйте запросы через GPROXY.

Учётные данные представляют сеанс OrcaTerm, а не SecretId Tencent Cloud или API-ключ отдельного поставщика моделей. Вход по Cookie остаётся необязательным способом импорта: вставьте заголовок Cookie с `ot_session=...` и сохраните `skey`, если он присутствует. При прямом импорте OAuth можно указать `access_token`; недостающие сведения об учётной записи запрашиваются перед генерацией.

Обновление соответствует клиенту: `OAuthRefreshToken` получает текущий токен доступа. Отдельный, не предусмотренный сервисом обмен refresh-токена не создаётся.

`base_url` переопределяет адрес LightAI без `/assistant`. `site_url` переопределяет адрес сервиса учётных записей для входа и обновления токенов. Адреса по умолчанию:

| Регион | LightAI | Учётные записи |
| --- | --- | --- |
| Китай | `https://lightai.cloud.tencent.com` | `https://orcaterm.com` |
| Международный | `https://lightai.tencentcloud.com` | `https://orcaterm.ai` |

## Квота учётной записи

Запрос квоты использует `POST /cgi/api?action=DescribeUserUsageStats` с `{"feature":"hunyuan_ai"}` в поле RPC `data`. Он возвращает **квоту вопросов к ИИ**, которую показывает настольный клиент: использованное количество, лимит, остаток и процент использования. Лимит `-1` означает отсутствие ограничения; отсутствующие счётчики остаются неизвестными. Пустой, некорректный ответ или квота другой функции не превращаются в нулевой баланс.

Публичный ответ `DescribeProductEditions`, проверенный 2026-10-24, указывал 1000 вопросов в месяц для базового тарифа, 6000 в месяц для профессионального и суточные периоды для пробных и доменных тарифов. Это публичные параметры тарифов, а не измеренный остаток конкретной учётной записи. Они не зашиты в запрос квоты. Из счётчика запросов не выводится денежный баланс или остаток токенов.

Границы периода показываются только при наличии в статистике ИИ явных временных меток `quotaStartDate` / `quotaEndDate` с часовым поясом. Время сброса не вычисляется из даты без часового пояса, окончания подписки или предполагаемого месячного расписания. Автоматическая покупка или сброс квоты не выполняются.

Счётчик не сообщает, какие текущие маршруты моделей LightAI используют общий лимит. Поэтому эти данные служат **только для наблюдения и отображения**. Они появляются в обычном представлении квот, но не блокируют локально все модели и не приводят к подсчёту запросов шлюза в неподтверждённом общем пуле. Ответы самого сервиса об исчерпании квоты обрабатываются обычным образом.

Анонимный запрос использования вернул `VERIFY_USER_FAILED`. Для получения фактического остатка нужен вход в учётную запись; такая проверка пока не выполнена.

## Границы поддержки

Сейчас поддерживается **только текст**. Изображения, аудио, содержимое файлов, клиентские инструменты-функции, история инструментов, принудительный выбор инструмента, структурированный вывод и несколько вариантов ответа отклоняются. Запрос сервиса на вызов инструмента OrcaTerm приводит к ошибке: GPROXY не выполняет терминальные команды и не подтверждает операции инструментов от имени вызывающей стороны.

Каждый запрос получает новый идентификатор диалога у сервиса и явно передаёт историю вызывающей стороны. Независимые клиентские диалоги не используют общий сеанс. Это не режим без хранения данных: срок хранения серверной истории определяет OrcaTerm. Канал не импортирует настройки подключений, учётные данные SSH, записи терминала или телеметрию настольного приложения.

В исследованном протоколе SSE не обнаружены подтверждённые поля количества токенов. Поэтому использование остаётся неотчётным, а не подменяется нулём. Квота учётной записи запрашивается отдельно; платное продолжение, сброс квоты и WebSocket не объявляются поддерживаемыми возможностями. Обнаружение моделей охватывает встроенные модели. Частные настройки сторонних моделей учётной записи не выдаются за идентификаторы встроенных моделей. Клиентские списки по-прежнему формируются из локального каталога GPROXY с фильтрацией по правам доступа.

Публичный каталог моделей и анонимные входные точки OAuth проверены 2026-10-24: WeChat и Tencent Cloud в Китае, а также Google в международном сервисе перенаправляли на соответствующие страницы авторизации. До завершения входа `OAuthExchangeToken` возвращал `TOKEN_EXPIRED`. Канал считает этот ответ ожиданием авторизации в пределах своего десятиминутного окна входа; другие ошибки не скрываются как ожидание.

Успешная выдача токена, генерация и обновление требуют настоящей учётной записи. Полная проверка с авторизацией пока не выполнена. Проверки со сценарным транспортом подтверждают обработку запросов и ответов, но не права подписки или успешный вызов реального сервиса. Международные адреса взяты из ветви настольного клиента, а не из отдельно перехваченного международного установочного экземпляра.

Публичный запрос каталога без учётных данных:

```http
POST https://dnspod.cloud.tencent.com/ajax/rainbow?action=getRainbowConfig
Content-Type: application/json

{"app":"ai","groups":["orcaterm.内置模型"],"options":{"enableEnv":1}}
```

Поле `model` ответа — идентификатор, передаваемый сервису; `displayName` и `text` — подписи. Отключённые записи (`weight=0`) исключаются. При ошибке обнаружения каталог не заменяется зашитым снимком.
