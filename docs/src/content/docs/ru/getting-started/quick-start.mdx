Установите и запустите GPROXY по инструкции [Загрузка и установка](/ru/download/#setup). Пользователи приложения завершают работу мастера настройки и открывают консоль в приложении. Пользователи CLI и контейнера открывают `http://127.0.0.1:8787/console/` и входят в систему с учётной записью администратора, созданной при первом запуске.

В этом примере используется служба, совместимая с OpenAI. Вам понадобится ключ API провайдера и ID модели, поддерживаемая этим сервисом.

<a id="1-add-a-provider"></a>

## 1. Добавьте провайдера

Откройте **Провайдеры** и создайте соединение:

- Назовите его `openai-main`.
- Для официального сервиса OpenAI выберите канал `openai`.
- Для другой совместимой службы выберите `custom`, введите ее базовый URL и выберите поддерживаемые протоколы, такие как завершение чата (`openai_chat`). Проверьте документацию провайдера на наличие этих значений.

Имя провайдера также можно использовать для прямых запросов. Несколько провайдеров могут использовать один и тот же канал с разными адресами и учётными данными.

<a id="2-add-and-test-a-credential"></a>

## 2. Добавьте и проверьте учётные данные

Откройте вкладку **Учётные данные** провайдера и добавьте ключ API провайдера. Для таких каналов, как Codex или Claude Code, выберите вариант входа и выполните шаги авторизации.

Используйте тестовое действие для учётных данных, выберите поддерживаемую модель и отправьте короткое сообщение. Тесты генерации отправляют реальный запрос провайдеру и могут быть платными. Сохраните рабочую ID модели для следующего шага.

Ключ провайдера остается в GPROXY. Ваш клиент использует ключ API шлюза, выданный GPROXY; это разные учётные данные.

<a id="3-create-a-model-route"></a>

## 3. Создайте маршрут модели

Откройте **Маршруты моделей**, создайте маршрут с именем `fast` и добавьте участника. Выберите `openai-main` и введите ID модели, которую вы только что протестировали. Пока сохраните уровень и вес по умолчанию.

Клиенты теперь могут запрашивать `fast`. Вы можете изменить провайдера, изменив участника маршрута. Прямые вызовы провайдеру также доступны без маршрута; см. [Модели и маршруты](/ru/guides/models/).

<a id="4-send-a-request"></a>

## 4. Отправьте запрос

Используйте ключ API шлюза, сохраненный во время установки, или создайте новый ключ в разделе **Моя учётная запись → Ключи**. Замените заполнитель ниже и при необходимости отрегулируйте порт.

```sh
export GPROXY_KEY='your-gproxy-api-key'
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"Hello. Please introduce yourself briefly."}]}'
```

Базовая настройка URL клиента OpenAI обычно принимает `http://127.0.0.1:8787/v1`. Поле, запрашивающее полный запрос URL, принимает адрес `/v1/chat/completions`, указанный выше.

См. [Первый запрос](/ru/getting-started/first-request/) для других протоколов и потоковой передачи или [CLI клиенты](/ru/guides/cli-clients/) для конфигурации Codex CLI и Claude Code.

<a id="5-check-usage"></a>

## 5. Проверьте использование

Откройте страницы запросов и использования консоли, чтобы проверить модель, провайдера, количество токенов и стоимость. Затраты зависят от настроенных правил ценообразования и не отражают непосредственно счёт провайдера. Поля использования, о которых не сообщает провайдер, могут быть пустыми.

<a id="troubleshooting"></a>

## Поиск неисправностей

| Результат | Сначала проверьте |
| --- | --- |
| Невозможно подключиться | Работает ли GPROXY, правильный ли адрес и порт |
| `401` | Предоставили ли вы действительный ключ шлюза GPROXY |
| `403` | Разрешение пользователя или ключа на доступ к целевой модели |
| `404 unknown_model` | Существует ли маршрут `fast`, включён ли он и есть ли в нём участники |
| `429` | Локальные лимиты, квоты провайдера и доступность учётных данных |
| ошибка провайдера или неподдерживаемая операция | результаты проверки учётных данных, ID модели, выбор протокола и конфигурация конечной точки |

Для управления с помощью сценариев см. примеры API в [Провайдеры](/ru/guides/providers/) и [Модели и маршруты](/ru/guides/models/).
