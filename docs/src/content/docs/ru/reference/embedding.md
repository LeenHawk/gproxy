`gproxy-sdk` — это встраиваемый дескриптор GPROXY. Это то, на чем построен сам шлюз, и приложение может связать его напрямую.

**То, что он продает, — это не клиент HTTP, а вызов с дисциплиной учётных данных объединенной аутентификации:** пул учётных данных, автоматическое обновление, переключение между провайдерами и дозированное урегулирование. Именно поэтому база данных внутри него не является обязательной. Claude меняет свой токен обновления при каждом обновлении, поэтому дескриптор, хранящий учётные данные в памяти, уничтожит учётные данные при первом обновлении.

Встройте `gproxy-sdk` через тег Git или зависимость пути. Библиотеки поддержки MIT также публикуются отдельно на crates.io.

```toml
[dependencies]
gproxy-sdk = { git = "https://github.com/LeenHawk/gproxy", tag = "v4.0.0" }
```

В рабочей области используется Rust версии 2024. В этом примере закреплена версия `4.0.0`; Rust v4 и API управления отличаются от v3.

<a id="assembling-one"></a>

## Сборка одного

```rust
use gproxy_sdk::{GproxyBuilder, SyncMode};

let gproxy = GproxyBuilder::sqlite("gproxy.db")
    .await?
    .master_key([0u8; 32])
    .sync_mode(SyncMode::Background)
    .build()
    .await?;

for channel in gproxy.channels() {
    println!("{} ({})", channel.display_name, channel.id);
}
println!("serving revision {}", gproxy.revision().0);
```

`build()` ничего не открывает. Он синхронизирует схему объекта (если не указано иное), создает строку настроек, собирает движок, загружает первый снимок и — в фоновом режиме — запускает циклы подписки и опроса.

**Секретный кодек никогда не выбирается неявно.** `master_key` соединяется с AES-256-GCM, `plaintext_secrets` — это явный отказ, а сборка ни с одним из них не отклоняется. Не существует тихого значения по умолчанию, которое оказалось бы открытым текстом.

<a id="features"></a>

## Функции

| Особенность | Эффект |
| --- | --- |
| имя одного канала (`codex`, `kiro`, `openai`, …) | скомпилировать этот канал и зарегистрировать его |
| `channels` | каждый канал в этой рабочей области |
| `postgres` / `mysql` | дополнительные драйвера, только родные. SQLite всегда доступен изначально |
| `libsql` | libSQL/Turso через конвейер Hrana HTTP, **каждая цель** |
| `d1` | маркер для привязки Cloudflare D1 |
| `memory` *(по умолчанию)* | локальный кеш процесса, изначально используемый по умолчанию |
| `redis` | для более чем одного экземпляра |
| `fs` *(по умолчанию)* | локальное хранилище файлов, только встроенное |
| `s3` | S3/R2 хранилище |
| `bundled-vocabulary` *(по умолчанию)* | Словарь DeepSeek для оценки токенов |
| `ts` | Объявления `ts-rs` для каждого DTO и каждого дескриптора канала |

Набор по умолчанию компилируется для `wasm32-unknown-unknown`, как и `libsql`.

Собственные сборки используют транспорт `reqwest`. Хост, которому нужен другой бэкэнд — `wreq` для эмуляции TLS, собственный стек для отпечатка пальца Codex CLI — включает эту функцию в клиентском ящике или передает сборщику собственный клиентский пул.

<a id="calling"></a>

## Вызов

```rust
let execution = gproxy
    .call(
        OperationKey { operation: Operation::GenerateContent, dialect: Dialect::OpenAi },
        request,
    )
    .scope("user:u-1")
    .attribution(UsageAttribution { user_id: Some("u-1".into()), ..Default::default() })
    .budgets(vec![BudgetOwner::new("user", "u-1")])
    .credentials(["cred-1".to_owned()].into())
    .send()
    .await?;

let (response, usage) = execution.into_parts();
```

`call` формирует запрос; `send` определяет название модели и выполняет план.

**Требуется область действия, и для нее не существует безопасного значения по умолчанию.** Это граница изоляции, внутри которой механизм хранит сходство учётных данных одного клиента API, поэтому значение по умолчанию будет означать, что незнакомцы будут делиться продолжениями.

`connect` — это тот же сборщик, использующий рукопожатие WebSocket.

`.channel("claudecode")` сужает набор кандидатов. Это сужение, а не выбор провайдера: канал существенно отличается от API-клиента — `claudecode` тратит подписку OAuth, в то время как `claudeapi` тратит ключ API на токен, с независимыми пулами квот и выставлением счетов — в то время как провайдер — это строка конфигурации, о которой никто за пределами экземпляра не должен знать. Закрепление канала оставляет дескриптору много работы: выбирать среди провайдеров этого канала, выбирать среди учётных данных провайдера и двигаться дальше внутри канала, если один из них терпит неудачу.

Все, что решил уровень приложения — разрешенные провайдеры и учётные данные, бюджетная цепочка, сеанс — **передается**. Ничто здесь не подтверждает подлинность личности.

В URL-адресах ресурсов используется `DefaultFetchPolicy`: встроенные прямые соединения, проверенные общедоступные адреса IP. URL-адреса домена отклоняются, если прокси-сервер разрешает их самостоятельно. Хост внедрения может явно настроить `AllowlistFetchPolicy` через `.fetch_policy(...)` для имен хостов, которые он контролирует; это делегирует исполнение назначения его прокси. На Wasm адресаты имен хостов по-прежнему зависят от элементов управления выходом платформы.

<a id="what-is-not-here"></a>

## Чего здесь нет

- **Идентификация.** Пользователи, ключи API, организации, команды, разрешения, подписки, лимиты запросов и эмитент OAuth принадлежат `gproxy-app`, который считывает одну и ту же долгосрочную версию из одного и того же пакета.
- **Аутентификация клиента.** Ничто здесь не определяет, кто является клиентом API.
- **Сервер.** Ни прослушивателя, ни маршрутизатора, ни промежуточного программного обеспечения, ни CLI.
- **Консоль.** Этот контейнер генерирует типы TypeScript, для которых записывается UI; UI — это приложение.
- **Выполнение.** Попытки, преобразование, переписывание, наблюдение, бюджеты и расчеты выполняются движком; этот ящик решает только, что ему передать.

<a id="management"></a>

## Управление

`gproxy.manage()` — это сторона записи: один метод доступа на каждое семейство конфигурации, все для одного и того же примитива фиксации.

| Семья | Строки | За пределами CRUD |
| --- | --- | --- |
| `providers()` | `providers` | `reset_routing_defaults` |
| `credentials()` | `credentials` | `reveal_secret`, `set_status`, `refresh`, `quota_probe`, `quota_read`, `quota_observations`, `quota_reset`, `health_reset`, `limit_status` |
| `models()` / `provider_models()` | каталог | |
| `routes()` / `route_members()` | маршрутизация | |
| `connection_profiles()` | исходящие стеки | |
| `settings()` | одна строка настроек | Только `get`/`update` |
| `rewrite()` | наборы правил, правила, вложения | `replace_rules` |
| `endpoints()` | `operation_rules`, `operation_endpoints` | |
| `quotas()` | `quotas` | `budget_status`, `reset_budget`, `limit_status`, `reset_limit` |
| `pricing()` | правила, тарифы, уровни | |
| `transfer()` | все настроено | `export`, `import` |
| `catalog()` | ничего, пока не применишь | `channels`, `default_models`, `apply_default_prices`, `tls_presets`, `rule_presets` |
| `connectivity()` | `provider_models` | `test`, `model_test`, `discover_models`, `apply_discovered` |
| `tokenizer()` | словарные файлы | `vocabularies`, `fetch`, `progress`, `delete`, `auth` |

Первая десятка — это обычные CRUD плюс партия. Идентификаторы предоставляются клиентом API, если они заданы, а в противном случае созданы, метки времени представляют собой миллисекунды Unix, десятичные дроби передаются как строки, а секрет учётных данных никогда не находится в DTO.

При записи присваиваются имена своим областям, и это единственное, что выбирает клиент API. Область состояния учётных данных использует дешевый путь перезагрузки, и он действителен **только** для записи, ограниченной секретом, сроком его действия и статусом жизненного цикла — все остальное, связанное с учётными данными, замораживается в моментальном снимке выполнения при сборке и требует полной перезагрузки.

<a id="queries"></a>

## Запросы

`gproxy.query()` — сторона чтения. Здесь ничего не пишет, поэтому ничего здесь не переносит ревизию.

| Семья | Ответы |
| --- | --- |
| `usage()` | `records`, `summary`, `group`, `trend` |
| `quota()` | `windows`, `settlements`, `credential_cycles`, `credential_observations`, `counted_windows`, `budget_status` |
| `logs()` | `list`, `detail(request_id)` |

**Агрегация происходит в Rust в рамках ограничения сканирования.** Поля с фиксированным использованием представляют собой выделенные столбцы с одной строкой для каждого физического вызова провайдера и без строк сводки по клиенту. Фильтры учётных данных провайдера и аутентификации работают в SQL. `summary`, `group` и `trend` складывают соответствующие строки и пользовательские количества в фрагменты, упорядоченные по ключам. Каждый агрегат занимает бюджет сканирования, по умолчанию равный 50 000 строк и ограниченный им, а достигший его агрегат возвращает `truncated: true` со счетчиком сканирования — никогда не меньшее число, представленное как вся правда. Тренд ограничивается вторым способом: нулевой или отрицательный сегмент, обратный диапазон и диапазон, дающий более 5000 сегментов, отвергаются.

Стоимость считывается из выделенных столбцов USD. `currency` — это `None`, когда ни одна запись не была оценена. `quantities` содержит счетчики носителей, инструментов и пользовательских счетчиков в виде десятичных строк.

**Управление списками страниц по смещению; страницы журнала запросов перемещаются курсором.** Это не выбор стиля: список управления представляет собой ограниченный набор страниц, которые человек просматривает, тогда как журнал запросов представляет собой поток, предназначенный только для добавления, заголовок которого продолжает двигаться во время чтения, а страница смещения над ней повторяет или пропускает строки. Курсор журнала состоит из двух половин — метки времени и идентификатора строки — потому что два запроса могут начаться в одну и ту же миллисекунду, а курсор, содержащий только метку времени, либо зацикливается на этой паре навсегда, либо пропускает ее.

**Ничто в `logs()` не редактируется.** Наблюдатель применил политику развертывания при *записи* этих строк, поэтому сохраненное уже является тем, что может быть показано. Хост не должен предполагать, что второй проход происходит при чтении: если секрет находится в базе данных, политика разрешает его там, и фильтрация при чтении не может отменить это.

<a id="synchronization"></a>

## Синхронизация

| | несет | Не удалось |
| --- | --- | --- |
| аннулирование общего кеша | «посмотри еще раз», в течение миллисекунд | потеря сообщений |
| опрос `settings.config_revision` | непреходящая истина, каждые 30 секунд | быть медленным |

В Wasm по умолчанию используется кэш, поддерживаемый базой данных, а синхронизация всегда **ручная**: изолят не переживает свой запрос, поэтому нет необходимости запускать фоновый цикл, а `tick()` в начале запроса представляет собой весь механизм.

```rust
// tick() = drain the delivered notifications, then poll the revision once.
instance.tick().await;
```

Слив достаточно дешев, чтобы его можно было выполнить по каждому запросу; опроса нет, поэтому хост, которому нужна только дешевая половина, может позвонить самостоятельно. Ручной режим устанавливает подписку во время сборки и отбрасывает ведущую подсказку о повторной синхронизации — первая загрузка *является* повторной синхронизацией — поэтому запись между сборкой и первым тактом не пропускается обоими механизмами одновременно.

<a id="type-export"></a>

## Тип Экспорт

```sh
GPROXY_TS_OUT=console/src/generated \
  cargo test -p gproxy-sdk --features ts export_types
```

Без переменной тест немедленно возвращается и ничего не записывает, поэтому `cargo test --all-features` остается герметичным, а сгенерированный каталог перезаписывается только намеренно. При этом каталог **очищается первым** — устаревшее объявление для DTO, которое больше не существует, будет продолжать проверку типов еще долго после того, как Rust его удалил — и индекс, реэкспортирующий все, записывается последним.

Там же находится каталог каналов. Консоль отображает форму провайдера на основе дескриптора, который возвращает сам канал, поэтому ее следует вводить по этому дескриптору, а не по копии, которая перемещается в следующий раз, когда канал добавляет ключ конфигурации.

Список экспорта написан вручную, поскольку Rust не может перечислять типы модулей во время выполнения. Именно этот список появился в версии 3 — был добавлен DTO, никто не запомнил список, и консоль молча осталась без типа для него — поэтому второй тест считывает собственный исходный код модуля и сравнивает его реэкспорт со списком. **Добавление DTO и забвение списка — это красная проверка, а не отсутствие файла.**

<a id="above-the-sdk"></a>

## Над SDK

Приложение, которому также нужны идентификационные ссылки `gproxy-app`, которые добавляют аутентификацию, допуск, семейства операций администратора и портала, а также эмитент OAuth, а также владеет транспортом **no**. `gproxy-host-axum` превращает их в поверхность HTTP, `gproxy-host-edge` монтирует тот же маршрутизатор в Worker, а `gproxy-host-tauri` привязывает поверхности управления к IPC.

Каждый из этих швов — это место, куда может войти монтажник. См. [Архитектура](/ru/introduction/architecture/).
