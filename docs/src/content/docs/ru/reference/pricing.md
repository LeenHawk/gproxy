Ценообразование отвечает на один вопрос при расчете: **сколько стоил этот обмен**, учитывая провайдера, модель провайдера и нормализованное использование канала.

Это происходит **внутри движка**, при расчете, поэтому бюджеты и наблюдатель видят одно и то же число. В версии 3 движок передавал использование, а уровень приложения снова оценивал его, что давало две временные семантики, два сопоставления моделей и два ответа на вопрос «что, если цены нет». v4 имеет по одному каждому из них.

Три таблицы в одной форме: строка `price_rules` выбирает модель, строки `price_rates` оценивают каждую метрику, а строки `price_tiers` корректируют лестницу токенов по размеру приглашения и уровню обслуживания.

<a id="rule-selection"></a>

## Выбор правила

Правило подходит, когда

- его провайдер является провайдером биржи **или не установлен** (глобальное правило);
- его шаблон подстановочного знака `modelPattern` соответствует названию модели **провайдера**;
- его `operation` соответствует запросу **или не установлен** (все операции).

**Правила провайдера предшествуют глобальным правилам.** В пределах одной области побеждает `(priority, id)` с наименьшим значением.

| Поле | Значение |
| --- | --- |
| `providerId` | `null` — глобальное правило |
| `modelPattern` | Шаблон подстановочного знака `*`/`?` для имени модели провайдера |
| `operation` | `null` охватывает все операции согласованной модели |
| `priority` | сначала опустить; id разрывает связи |
| `currency` | Должно быть `USD`; все цены и расчеты используют USD |
| `enabled` | |

<a id="no-rule-at-all"></a>

### Никакого правила вообще

Обмен **не имеет цены**: он ничего не стоит, он по-прежнему рассчитывается, и его использование приносит

```json
{"dimensions": {"unpriced": "true"}}
```

Это сигнал, а не отказ. Оператор хочет знать, что модель обслуживается бесплатно; они не хотят, чтобы запрос был отклонен, потому что никто еще не ввел цену.

<a id="rate-rows"></a>

## Оценить строки

Строка тарифа — это базовая цена одного показателя.

| Поле | Значение |
| --- | --- |
| `metric` | встроенный ключ или любой пользовательский ключ, который излучает канал |
| `unit` | `token`, `count`, `second` или `character` |
| `unitQuantity` | положительный знаменатель: 1 000 000 токенов, 1 изображение, 60 секунд |
| `value` | неотрицательная цена для единиц `unitQuantity` в валюте правила |
| `conditions` | `null` — резервная строка; в противном случае непустой объект имен измерений для скаляров, **все** из которых должны соответствовать |
| `priority` | первой нижней среди строк одной метрики |

Для одной метрики условные строки пробуются в порядке `(priority, id)`, и побеждает первая, все условия которой соответствуют размерам поселения; в противном случае применяется резервная строка. **Выбранный условный тариф заменяет базовый тариф** и не суммируется с ним.

```json
[{"metric":"input_tokens",  "unit":"token","unitQuantity":"1000000","value":"0.40"},
 {"metric":"output_tokens", "unit":"token","unitQuantity":"1000000","value":"1.60"},
 {"metric":"image_outputs", "unit":"count","unitQuantity":"1","value":"0.04",
  "conditions":{"quality":"hd","size":"1024x1024"},"priority":0}]
```

<a id="the-rule-that-stops-double-billing"></a>

### Правило, предотвращающее двойное выставление счетов

**Тарифы должны учитывать непересекающиеся количества.** Кэшированные данные удаляются из обычных данных; с подмножества токенов рассуждения или медиа-токенов нельзя взимать плату снова, если они уже выставлены через совокупный счет. Выходные данные за изображение и за токен являются *альтернативными* базами, если провайдер действительно не взимает плату за оба.

Общая строка `tool_calls` и конкретная строка `web_searches` не должны одновременно выставлять счет за один и тот же вызов. И клиент, *объявляющий* инструмент, не является оплачиваемым выполнением на стороне сервера.

<a id="the-metrics"></a>

## Метрики

**Токены** — условно на 1 000 000:

```text
input_tokens          output_tokens           cached_input_tokens
cache_creation_tokens
reasoning_tokens      image_input_tokens      image_output_tokens
audio_input_tokens    cached_audio_input_tokens  audio_output_tokens
video_input_tokens    video_tokens
```

Запись в кэш использует метрику `cache_creation_tokens`. Условие тарифа `{"ttl_seconds":43200}` выбирает цену записи на 12 часов; без этого условия действует базовая цена. Каждая группа записанных токенов тарифицируется отдельно. Чтение остается одним счетчиком `cached_input_tokens`, без TTL. Переопределения уровней: `cacheCreationPerMillion: [{"ttlSeconds":43200,"price":"5"}]`; `ttlSeconds: null` задает базовую цену. Цена указана за миллион токенов и не умножается на TTL.

**Счетчики, секунды и символы:**

```text
image_outputs   video_outputs   audio_seconds   video_seconds   audio_characters
search_units    web_searches    web_fetches     file_searches
code_interpreter_sessions       tool_calls      requests
```

Показатель вне этого списка по-прежнему оценивается, пока он указан в строке тарифа. Список — это то, что представляют собой встроенные клавиши, а не фильтр.

`requests` — это плата за запрос: взимается плата за один запрос за **ценовый обмен**.

<a id="tiers"></a>

## Уровни

Строка `price_tiers` переопределяет **только цены токенов**, всегда за миллион.

| Поле | Значение |
| --- | --- |
| `serviceTier` | `null` делает его **контекстным** уровнем; иначе `standard`, `priority`, `flex`, `batch`, … |
| `minPromptTokens` | неотрицательный инклюзивный порог; по умолчанию 0 |
| `multiplier` | для уровня обслуживания: на что умножить унаследованную цену. Для строк, предназначенных только для контекста, параметр не задан |
| `*_per_million` | явная цена за один вид токена |

Явные столбцы: `input`, `output`, `cache_read`, `cache_creation_per_million`, `reasoning`, `image_input`, `image_output`, `audio_*` и `video_*`.

**Длина подсказки учитывает ввод, а также операции чтения и записи в кэш, однократно.**

<a id="composition-per-token-kind"></a>

### Состав по типу токена

1. **Базовая ставка** — строка `price_rates` для этого показателя, сначала условные строки.
2. **Уровень контекста** — самый высокий уровень `minPromptTokens`, достигнутый среди строк с **отсутствующим** уровнем обслуживания. Его явные цены заменяют базовые цены для устанавливаемых им видов.
3. **Уровень обслуживания** — наивысший достигнутый порог среди строк, в которых указан *фактический* уровень обслуживания. Явная цена здесь **безоговорочно выигрывает**; в противном случае база с учетом контекста умножается на `multiplier` этой строки (по умолчанию 1).

Равные пороги пробивают нижний `(priority, id)`. `null` наследует; ноль **явно свободен** и не отсутствует.

Множитель никогда не применяется к инструментам или средствам массовой информации *подсчитывает* — только к ценам токенов.

:::предупреждение[Явная цена уровня заменяет всю лестницу] С базовой входной ценой 1, контекстным шагом `≥ 200,000 → 2` и 300 000 токенов подсказки:

| Строка `batch` | Эффективная скорость ввода |
| --- | --- |
| `{"serviceTier":"batch","multiplier":"0.5"}` | `2 × 0.5 = 1` |
| `{"serviceTier":"batch","inputPerMillion":"0.5"}` | `0.5` — шаг 200 тыс. потерян |
| `{"serviceTier":"batch","minPromptTokens":200000,"inputPerMillion":"1"}` | `1` |

Повторите явную цену уровня для каждого порога, который она должна покрыть, или используйте множитель. :::

<a id="two-special-cases"></a>

### Два особых случая

- **Рассуждение — это подмножество результатов.** Если существует цена рассуждения, жетоны рассуждения вычитаются из `output_tokens` и взимаются отдельно. В противном случае они остаются внутри выхода и взимаются один раз.
- **Чтение кэша без цены наследует входную цену.** Любой *другой* вид без цены является бесплатным. Такая асимметрия намеренна: чтение кэша однозначно является входным токеном, а отсутствие цены на аудио или видео — это пробел в конфигурации, который оператор должен рассматривать как ноль.

<a id="requested-versus-served"></a>

### Запрошено или обслужено

Взимается плата за тот уровень, который **фактически указан в ответе**, а не тот, который запрошен в запросе. Запрос `priority` на понижение версии провайдера обрабатывается в строке понижения.

<a id="everything-else"></a>

## Все остальное

За каждую метрику, не являющуюся токеном, взимается плата

```text
amount × value / unitQuantity
```

и **никогда не умножается на уровень обслуживания**.

<a id="editing-prices"></a>

## Редактирование цен

```sh
curl -s http://127.0.0.1:8787/admin/api/price-rules  -H "Authorization: Bearer $GPROXY_KEY"
curl -s http://127.0.0.1:8787/admin/api/price-rates  -H "Authorization: Bearer $GPROXY_KEY"
curl -s http://127.0.0.1:8787/admin/api/price-tiers  -H "Authorization: Bearer $GPROXY_KEY"
```

Каждое семейство использует обычные пять маршрутов плюс пакет, а пакет — это одна фиксация ревизии, сколько бы строк она ни называла.

В прилагаемом каталоге они указаны для моделей, о которых известно в этом выпуске:

```sh
curl -s -X POST http://127.0.0.1:8787/admin/api/default-model-catalog/apply-prices \
  -H "Authorization: Bearer $GPROXY_KEY" -H 'content-type: application/json' \
  -d '{"providerId":"…","modelIds":["gpt-4o-mini"],"overwrite":false}'
```

Без провайдера используются собственный шаблон и приоритет каталога, поэтому одно правило оценивает эту модель везде, где она обслуживается; с провайдером буквальное имя становится шаблоном с нулевым приоритетом. **`overwrite: false` делает повторное применение безопасным**: правило, отредактированное оператором, сохраняет свои изменения и сообщается как пропущенное.

Строка с неверной ценой удаляется с предупреждением при сборке и **не** блокирует моментальный снимок. Одна опечатка в десятичной дроби не должна отключать экземпляр, который в противном случае обслуживает трафик.

<a id="budgets-spend-the-result"></a>

## Бюджеты тратят результат

Бюджет — это строка `quotas`, метрика которой равна `cost` в USD. Прием передает движку цепочку клиентов API — `[api_key?, user, team?, org?]` — и применяется **каждый** включенный бюджет **любого** владельца в цепочке.

Расходы рассчитываются после звонка провайдера. Текущие и одновременные запросы могут превышать бюджет. См. [Разрешения, лимиты запросов и бюджеты](/ru/guides/permissions/) о владении и проверках.

<a id="token-estimation"></a>

## Оценка токена

Когда оплачиваемый ответ вообще не используется, движок сам подсчитывает токены и помечает запись `estimated = true`. При подсчете используется локальный словарь: кодировки tiktoken для моделей семейства GPT-, в противном случае словарь — имена строк каталога модели, в противном случае — встроенный словарь DeepSeek.

```sh
curl -s http://127.0.0.1:8787/admin/api/tokenizer-vocabs -H "Authorization: Bearer $GPROXY_KEY"
curl -s -X POST http://127.0.0.1:8787/admin/api/tokenizer-vocabs \
  -H "Authorization: Bearer $GPROXY_KEY" -H 'content-type: application/json' \
  -d '{"repo":"…","filename":"tokenizer.json","modelId":"…","setAsDefault":true}'
```

При выборке файл загружается через настроенное файловое хранилище, затем вставляется строка и указывает на нее модель и значение по умолчанию — **строка и оба указателя в одной фиксации ревизии**. Байты попадают перед строкой: строка, указывающая на объект, который никогда не был записан, приведет к сбою при каждой перезагрузке, а объект без строки — это просто пустая трата места.

Без файлового хранилища вся семья отвечает "неподдерживается": байты девать некуда.
