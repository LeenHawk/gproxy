<a id="docker"></a>

## Докер

Одни и те же изображения опубликованы в четырех реестрах для amd64, Arm64 и riscv64. Выберите тот, который вам ближе всего:

| Реестр | Изображение |
| --- | --- |
| Докер-Хаб | `gproxy2/gproxy` |
| GitHub | `ghcr.io/leenhawk/gproxy` |
| GitLab | `registry.gitlab.com/leenhawk1/gproxy` |
| CNB | `docker.cnb.cool/leenhawk/gproxy` |

В стабильных версиях используются теги `vX.Y.Z`, в бета-версиях — `staging`, а в моментальных снимках разработки — `nightly`; добавьте `-musl` для изображений musl. Старые теги версии 3 не поддерживают версию 4.

```sh
export GPROXY_IMAGE='gproxy2/gproxy:<tag>'
# Set GPROXY_MASTER_KEY to your saved 32-byte key (64 hex digits or base64).
docker run -d --name gproxy --restart unless-stopped \
  -p 127.0.0.1:8787:8787 \
  -v gproxy-data:/app/data \
  -e GPROXY_MASTER_KEY \
  "$GPROXY_IMAGE"
docker logs gproxy
```

Сохраните учётные данные администратора из первого журнала запуска, затем откройте `/console/`. Образ запускается как `65532:65532`, поэтому этому пользователю должен быть доступен для записи каталог, смонтированный с помощью привязки. При замене контейнера сохраняйте том `/app/data`.

<a id="render"></a>

## Оказывать

1. Используйте карту рендеринга выше и просмотрите корневой план `render.yaml`: бесплатный веб-сервис, использующий внешнюю базу данных PostgreSQL.
2. Установите `GPROXY_DATABASE_URL` на внешнее соединение PostgreSQL URL и разверните службу. База данных должна быть доступна из Render; сохраните все параметры SSL, требуемые вашим провайдером базы данных. Render генерирует пароль администратора и ключ шифрования.
3. Откройте настройки **Среды** службы и сохраните `GPROXY_ADMIN_PASSWORD` и `GPROXY_MASTER_KEY`. Посетите сервис URL, затем `/console/` и войдите в систему как `admin`.

Шаблон не создает базу данных. Веб-сервис Render использует бесплатный план; Цены и ограничения на внешнюю базу данных зависят от вашего провайдера. Бесплатные веб-сервисы переходят в режим ожидания, когда они простаивают, поэтому следующий запрос может занять больше времени. Проверка работоспособности — `/healthz` на порту `8787`.

<a id="heroku"></a>

## Хероку

1. Создайте мастер-ключ с помощью `openssl rand -hex 32` и сохраните его.
2. Используйте карту Heroku выше, выберите имя приложения и регион и введите ключ как `GPROXY_MASTER_KEY`.
3. Ознакомьтесь с базовым веб-диностендом и надстройкой `heroku-postgresql:essential-0`, а затем разверните их.
4. Получите `GPROXY_ADMIN_PASSWORD` из **Настройки → Показать параметры конфигурации** и войдите в систему как `admin` на `/console/`.

Корневые `app.json` и `heroku.yml` используют `deploy/serverless/Dockerfile`. Запись Node.js прослушивает динамический `PORT` Heroku, а общий шлюз читает `DATABASE_URL`. Он поддерживает назначенную Heroku среду выполнения UID. Локальные файлы являются временными; конфигурация, учётные данные, использование и состояние кэша хранятся в PostgreSQL.

<a id="northflank"></a>

## Северный фланг

1. Создайте шаблон в своей учётной записи или команде Northflank. Переключитесь в редактор JSON и вставьте [шаблон JSON](https://github.com/LeenHawk/gproxy/blob/dev/deploy/northflank/template.json).
2. Установите имя шаблона GPROXY. При необходимости настройте аргумент `PROJECT_NAME` и `region` (`europe-west`) узла Project, затем сохраните и запустите его.
3. Рабочий процесс создает проект, частную базу данных PostgreSQL, секретную группу и общедоступную службу GPROXY. Обе рабочие нагрузки используют `nf-compute-20`; база данных запрашивает 4 ГБ хранилища. Просмотрите эти планы перед запуском.
4. Откройте секретную группу `gproxy-secrets` проекта и сохраните сгенерированные `GPROXY_ADMIN_PASSWORD` и `GPROXY_MASTER_KEY`. Откройте общедоступный HTTPS URL службы, затем `/console/` и войдите в систему как `admin`.

[общие ссылки на шаблоны](https://northflank.com/docs/v1/application/infrastructure-as-code/share-a-template) Northflank генерируются на основе сохраненного в учётной записи шаблона. Этот репозиторий предоставляет импортируемый шаблон; у него еще нет опубликованной ссылки на ресурс Northflank. Чтобы предоставить кнопку прямого развертывания, сохраните шаблон и создайте общедоступную ссылку. Прежде чем поделиться им, проверьте область доступа и срок его действия.

Секретная группа связывает `POSTGRES_URI` базы данных с `GPROXY_DATABASE_URL`. Служба собирает `deploy/serverless/Dockerfile` из ветки репозитория `dev` с `deploy/serverless` в качестве контекста сборки. Northflank сохраняет сгенерированные секреты при каждом запуске шаблона. При проверке готовности используется `/healthz` на порту `8787`.

<a id="operating-the-service"></a>

## Эксплуатация услуги

- Сохраняйте базу данных и `GPROXY_MASTER_KEY` во всех обновлениях. Сделайте резервную копию обоих. Эти шаблоны принимают `GPROXY_DATABASE_URL` или `DATABASE_URL` платформы.
- Сборки загружают последнюю стабильную версию по умолчанию (`GPROXY_RELEASE_VERSION=latest`) и проверяют SHA-256. Для обновления очистите кэш сборки платформы и выполните повторное развертывание. Чтобы закрепить версию, установите для этого аргумента сборки Docker тег выпуска; выпуск должен содержать как бессерверные архивы Linux, так и `SHA256SUMS`.
- Шаблоны начинаются с одного экземпляра приложения. Их общий кеш хранится в PostgreSQL с использованием существующего бессерверного хоста.
- Установите для `GPROXY_PUBLIC_BASE_URL` общедоступный источник HTTPS при использовании OAuth или URL-адресов опубликованных файлов. Эти шаблоны не поддерживают хранение файлов. Используйте собственную сборку CLI для поддержки файловой системы или хранилища объектов. IP-адреса клиентов берутся из узла сокета, которым может быть маршрутизатор платформы; пересылаемые заголовки client-IP не являются доверенными.
- Собственный хост поддерживает HTTP, SSE и WebSocket. Тайм-ауты маршрутизатора платформы, ограничения простоя и перезапуски по-прежнему применяются; эти шаблоны не снимают эти ограничения.

Информацию о Workers и развертывании функций см. в [Руководство по Cloudflare, Netlify и Vercel](/ru/deployment/edge/).
