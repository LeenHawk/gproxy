---
title: "Миграция v3 на v4"
description: "Автоматическая миграция при запуске версии 4 с существующей базой данных версии 3."
---

**Замените двоичный файл и запустите его с существующей конфигурацией.** Версия 4 распознает базы данных версии 3 на SQLite, PostgreSQL, MySQL и D1 и автоматически обновляет их. Сохраните тот же каталог данных, путь к базе данных и `GPROXY_MASTER_KEY`; экспорт, новый каталог или сброс пароля не требуются. Существующие имена пользователей, пароли и ключи API продолжают работать.

<a id="sqlite-file-migration"></a>

## Миграция файлов SQLite

Прежде чем привязать свой порт HTTP, v4 делает полный снимок SQLite, включая зафиксированное содержимое WAL, и импортирует его во временную базу данных рядом с оригиналом. Он открывает учётные данные с помощью существующего мастер-ключа и сохраняет хэши паролей Argon2 пользователей. Только после успешного импорта и сборки моментального снимка исходный путь к базе данных заменяется. Он сохраняет резервную копию `gproxy.db.v3-*.bak` рядом с этим путем и записывает ее имя.

Неудачное преобразование не заменяет оригинал. Устраните указанную причину (например, восстановите существующий мастер-ключ) и начните заново. Прерывание перед заменой оставляет v3 на месте; после замены реестр миграции v4 делает последующие запуски обычными запусками v4. Повторного импорта нет.

Запустите один модуль записи базы данных во время обновления, как и в случае других миграций схемы. Остановите v3 перед запуском v4. Запуск обоих развертываний с одними и теми же учётными данными OAuth также может сделать недействительными токены обновления независимо от миграции базы данных.

<a id="postgresql-mysql-and-d1"></a>

## PostgreSQL, MySQL и D1

Сохраните исходное соединение URL или D1 и мастер-ключ. Никакого экспорта или новой базы данных не требуется. Собственные сборки PostgreSQL/MySQL должны включать соответствующий драйвер.

При миграции проверяется исходная конфигурация и шифрование учётных данных, а затем переименовываются старые таблицы в `gproxy_v3_<original-name>`. Эти таблицы сохраняют исходные данные. В новых таблицах версии 4 используются исходные имена. Конфигурация, идентификаторы и история использования преобразуются до того, как экземпляр откроется для трафика.

- **PostgreSQL** использует блокировку сеанса и переименовывает исходные таблицы за одну транзакцию.
- **MySQL** сохраняет блокировку сеанса при неявных фиксациях DDL и переименовывает все исходные таблицы с помощью одного оператора `RENAME TABLE`.
- **D1** использует пакеты транзакций для переименования, а также аренду миграции и проверку держателя для каждого пакета записи. Прерванная аренда истекает в течение 60 секунд.

`gproxy_v3_upgrade` хранит прогресс. Его поле `report_json` сохраняет пропущенные записи и предупреждения об изменении семантики. Контрольная точка импорта идентичности и использования между пакетами. После прерывания следующий запуск или запрос Worker возобновляет незавершенную работу. Частично перенесенный экземпляр не обслуживает трафик и не загружает нового администратора.

После сбоя старые таблицы остаются под архивными именами, а новые таблицы могут содержать завершенные части импорта. Исправьте сообщенную ошибку и перезапустите, чтобы возобновить работу. Не удаляйте таблицу выполнения и не переименовывайте архивы во время миграции. Чтобы вернуться к версии 3, остановите все экземпляры и восстановите резервную копию перед обновлением; не указывайте v3 на частично перенесенную базу данных. Сохраняйте архивированные таблицы до тех пор, пока обновление не будет проверено.

<a id="what-carries-over"></a>

## Что переносится

| Данные | Результат |
| --- | --- |
| Провайдеры и учётные данные | Известные названия каналов и конфигурации переведены; секреты повторно шифруются с использованием настроенного ключа. |
| Маршруты и участники | Имена общедоступных моделей становятся именами маршрутов. Дополнительные имена получают отдельные маршруты с скопированными участниками. |
| Пользователи, пароли, ключи API, организации и команды | Хэши паролей и дайджесты ключей API сохраняются. |
| Цены и бюджеты | Переведено на модули v4. Значения за пределами 9 десятичных знаков используют округление до ближайшего четного значения и сообщаются. |
| Разрешения, лимиты запросов и перезаписи | Поддерживаемые формы переносятся; сообщается об изменениях и несопоставимых формах. |
| История использования (импорт SQLite) | Импортируется ограниченными партиями с исходным количеством токенов, атрибуцией и согласованными затратами; никаких переоценок или урегулирования квот. Дополнительные поля v3 остаются в `metrics.v3`. |
| Захваты, журналы запросов, сеансы и история аудита | Сохраняется в резервной копии v3. Существующим сеансам браузера требуется новый вход в систему. |

Разрешения группы и организации расширяются до пользовательских правил для каждого импортированного участника, включая отключенных пользователей. В отчете перечислены все результирующие правила; группы без импортированных участников считаются пропущенными. Эти правила фиксируют членство во время миграции: последующие изменения членства не обновляют их. Это исправление применяется к новому импорту версии 3 и не восстанавливает разрешения, утраченные при уже завершенном обновлении.

Провайдеры, у которых нет переводимого канала/конфигурации, остаются позади вместе со своими зависимыми строками и с явным отчетом. При этом не игнорируются ошибки ввода-вывода базы данных или неправильные ключи шифрования. Просмотрите отчет о запуске на предмет упущений или изменений разрешений, связанных с конкретным каналом.

`gproxy migrate` использует тот же путь автоматического обновления. Когда база данных становится версии 4, в реестре SeaORM `seaql_migrations` фиксируются изменения ее схемы. `migrate --status` сообщает только о состоянии и никогда не выполняет обновление до версии 3.

<a id="optional-import-a-separate-backup-or-export"></a>

## Необязательно: импортируйте отдельную резервную копию или экспортируйте.

Для намеренного импорта в другой экземпляр по-прежнему доступна явная команда:

```sh
gproxy --data-dir ./other-instance migrate
gproxy --data-dir ./other-instance import --from-v3 /path/to/v3-backup.db
```

При использовании этой явной команды зашифрованному источнику требуется `--source-master-key` или `GPROXY_IMPORT_SOURCE_MASTER_KEY`. Место назначения должно быть пустым или содержать неполный предыдущий импорт. `--skip-unmappable-providers` соглашается на политику пропуска, которую уже использует автоматический запуск.

JSON из `POST /admin/api/export` v3 также принимается. Экспортируйте с помощью `{"include_secrets": true}`. В отличие от SQLite, в этом экспорте не учитываются хэши паролей, разрешения, лимиты запросов и модели провайдеров. Используйте `--admin-password`, чтобы установить пароль консоли при импорте экспорта JSON без хэшей; прямая миграция SQLite в этом не нуждается.
