title: "Что такое GPROXY?"
description: "Узнайте, что делает GPROXY, какие протоколы он поддерживает, а также основные концепции конфигурации."
---


GPROXY — это автономный шлюз LLM API. После подключения учётных записей провайдера клиентам потребуются только URL шлюза, ключ API шлюза и название модели.

Он выбирает провайдеров и учётные данные, при необходимости преобразует форматы запросов и ответов, обеспечивает соблюдение правил и ограничений доступа, а также записывает использование и затраты. GPROXY не запускает модели; служба провайдера выполняет логический вывод.

<a id="when-to-use-it"></a>

## Когда его использовать

- Управляйте несколькими учётными записями провайдеров с помощью централизованной аутентификации и аварийного переключения.
- Дайте команде стабильные названия моделей, чтобы изменения провайдера не требовали редактирования каждого клиента.
- Подключите Codex CLI, Claude Code и аналогичные инструменты через один шлюз с записью использования для каждого пользователя.
- Встроить функциональность шлюза в приложение Rust; см. [Встраивание ядра](/ru/reference/embedding/).

<a id="supported-protocols"></a>

## Поддерживаемые протоколы

Основными форматами являются OpenAI Chat Completions, OpenAI Responses, Claude Messages и Gemini GenerateContent, включая потоковую передачу. GPROXY напрямую преобразует форматы клиента и провайдера, если они различаются.

Существуют также API для эмбеддингов, переранжирования, изображений, аудио, видео, файлов и реального времени. Их доступность зависит от канала, модели и развертывания. Преобразование формата не может добавить возможности, которых нет у провайдера. Список интерфейсов см. в [Маршрутизация и конечные точки](/ru/reference/routing-table/).

<a id="key-concepts"></a>

## Ключевые понятия

| Концепция | Значение |
| --- | --- |
| Канал | Адаптер для семейства провайдеров, определяющий аутентификацию, форматы и поддерживаемые операции; например `openai`, `codex` или `custom`. |
| Провайдер | Сохраненное соединение с провайдером с именем, каналом, адресом, конфигурацией и пулом учётных данных. |
| учётные данные | Ключ провайдера API, токен OAuth или файл cookie. Провайдер может хранить несколько учётных данных. |
| Маршрут модели | Имя модели, ориентированной на клиента, с одним или несколькими членами провайдера/модели, весами и резервными уровнями. |
| Ключ API шлюза | Ключ, выданный GPROXY, связанный с пользователем, разрешениями и бюджетами. Он отделен от ключа провайдера. |
| Правило перезаписи | Правило для системного текста, точек кэширования, полей JSON, текста или заголовков. |

Секреты шифруются при настройке мастер-ключа. Без него CLI сохраняет секреты в незашифрованном виде и печатает предупреждение. См. [Конфигурация](/ru/reference/configuration/).

<a id="deployment-options"></a>

## Варианты развертывания

| Вариант | Использование |
| --- | --- |
| Приложение | Использование на настольном или мобильном устройстве с помощью мастера настройки и консоли в приложении. |
| CLI / контейнер | Развертывание сервера с API-интерфейсами HTTP и консолью браузера. |
| Cloudflare Workers | Edge-развертывание с удаленным хранилищем и поддержкой WebSocket/Realtime. |

См. [Скачать и установить](/ru/download/) для получения информации об ограничениях пакетов и платформы. При обновлении с версии 3 сначала прочтите [руководство по миграции](/ru/deployment/v3-to-v4/).

<a id="model-names-and-request-urls"></a>

## Названия моделей и URL-адреса запросов

Используя маршрут `fast`, отправьте `model: "fast"` на `/v1/chat/completions`.

Чтобы напрямую обратиться к провайдеру, используйте `/openai-main/v1/chat/completions` и укажите модель провайдера ID. Маршрут в пространстве имен, такой как `acme/fast`, также можно вызвать через `/acme/v1/chat/completions` с помощью `model: "fast"`.

См. [Модели и маршруты](/ru/guides/models/) для порядка разрешения и ограничений именования или следуйте [Быстрый старт](/ru/getting-started/quick-start/) для первой настройки.
