## v4.1.0

> Smaller capture storage, configurable payload retention, expanded Linux packages, and improved Console and upstream compatibility.

### English

#### Added

- Capture storage now compresses native payloads, deduplicates request bodies and headers, and coalesces stream segments while preserving SSE, NDJSON and WebSocket message boundaries.
- Configurable capture payload retention, defaulting to 7 days and 2 GiB. Expired or over-budget payloads are removed while request metadata and associations remain available; in-progress captures are excluded.
- Batch and delete-all actions for request logs and usage records, including desktop IPC support.
- musl Applications for x86_64, ARM64 and RISC-V, with ZIP, signed Alpine APK and DEB packages. musl DEBs include a private Alpine graphical runtime and use Bubblewrap on Debian/Ubuntu desktops.
- Signed Alpine APKs for the full and headless CLI on all three Linux architectures.
- Console system-theme selection, signed publisher announcements filtered by version/channel, and a download page with GitHub, GitLab and CNB sources.

#### Fixed

- Accept streaming tool arguments delivered only with the completed event, and emit protocol-specific buffered SSE heartbeats.
- Improve Claude Code, Codex, Grok Build and Antigravity request identity, model discovery, TLS and billing compatibility with the supported upstream clients.
- Preserve more OpenAI/Codex model capabilities and limits in typed catalogs and Console editing.
- Start all-time usage trends at the first recorded request and bind history deletion operations correctly in desktop builds.
- Repair HarmonyOS runtime packaging and local sideload-signing paths; HarmonyOS support remains experimental.
- Use a free Render service with an external database in the deployment template.

#### Changed

- Stable releases refresh Console, documentation and Rust registry dependencies before tagging, and stop when updates need validation and a commit. Upstream-required compatibility version lines remain enforced.
- Upgrade the frontend toolchain to TypeScript 7 with the official TypeScript 6 API compatibility package for ESLint. Refresh documentation dependencies and retain the HTTP cache security patch on the newer dependency.
- Update application/store metadata to 4.1.0 and Android version code 4001000.

#### Upgrade notes

- Back up the database before upgrading. Startup applies the new capture-storage migration; older versions do not recognize the new migration ledger entry, so downgrading requires restoring a compatible backup.
- Review the new retention settings if you need historical payloads for longer than the defaults. The 2 GiB budget measures encoded capture payloads, not the database file size; SQLite reuses freed pages.
- Alpine APKs require apk-tools 3 and the GPROXY public signing key supplied in musl ZIPs. musl Application DEBs require Bubblewrap user namespaces. GNU DEBs remain available for conventional glibc installations.

### 简体中文

#### 新增

- 请求日志存储支持原生负载压缩、请求体与请求头去重，并合并流式分段，保留 SSE、NDJSON 和 WebSocket 消息边界。
- 可配置的请求体保留策略，默认保留 7 天、最多 2 GiB。过期或超出预算的负载会被清理，元数据和关联记录仍保留；进行中的请求不参与清理。
- 请求日志和用量记录支持批量删除、全部删除，并接入桌面 IPC。
- 新增 x86_64、ARM64、RISC-V 的 musl 应用版，提供 ZIP、签名 Alpine APK 和 DEB。musl DEB 内置独立的 Alpine 图形运行库，通过 Bubblewrap 在 Debian/Ubuntu 桌面启动。
- 三种 Linux 架构的完整 CLI、无头 CLI 均提供签名 Alpine APK。
- 控制台支持跟随系统主题、按版本和通道筛选的签名公告；下载页支持 GitHub、GitLab、CNB 来源切换。

#### 修复

- 接受仅在完成事件中给出工具参数的流式响应，并按协议生成缓冲 SSE 心跳。
- 改进 Claude Code、Codex、Grok Build 和 Antigravity 与已支持上游客户端之间的请求标识、模型发现、TLS 和计费兼容性。
- 在强类型模型目录和控制台编辑中保留更多 OpenAI/Codex 模型能力与限制。
- 全时段用量趋势从第一条记录开始，修复桌面历史删除操作的 IPC 绑定。
- 修复鸿蒙运行库打包和本地侧载签名路径；鸿蒙支持仍为实验性功能。
- Render 部署模板使用免费服务和外部数据库。

#### 调整

- 正式版打标签前刷新前端、文档站和 Rust 注册表依赖；更新需要验证和提交时停止发布，同时保留上游要求的兼容版本线。
- 前端编译工具升级至 TypeScript 7，按官方方案为 ESLint 提供 TypeScript 6 兼容 API。更新文档依赖，并将 HTTP 缓存安全补丁保留在新版依赖上。
- 应用及商店元数据更新至 4.1.0，Android 版本号更新为 4001000。

#### 升级说明

- 升级前请备份数据库。启动时会执行新的日志存储迁移；旧版不能识别新的迁移记录，回退时需要恢复兼容的备份。
- 如果需要长期保留请求体，请检查新的保留策略。2 GiB 限制针对编码后的捕获负载，不是数据库文件大小；SQLite 会复用释放的页面。
- Alpine APK 需要 apk-tools 3 和 musl ZIP 中提供的 GPROXY 签名公钥。musl 应用 DEB 需要系统允许 Bubblewrap 用户命名空间；普通 glibc 系统仍可选择 GNU DEB。
