## v4.1.11

> Copilot CLI and Antigravity IDE client identities, upstream-aligned credential lifecycles, and a Microsoft Store CLI that starts without administrator rights.
>
> Copilot 改用 CLI 身份、Antigravity 以 IDE 身份接入，凭证生命周期对齐上游客户端，Microsoft Store 版 CLI 无需管理员权限即可启动。

### English

#### Added

- Present the Antigravity channel as the Antigravity IDE. Login, token, Code Assist setup and userinfo calls follow the IDE (IDE scopes, no PKCE, IDE client metadata); inference, model catalogue and quota calls carry the IDE language server's user agent, and the catalogue request names the project. The SDK `antigravity` TLS preset uses the IDE user agent.
- Android: warn at startup when Android System WebView is older than version 111, which the console requires, and offer its app store page. On older WebViews the console's colours turned transparent and dialogs overlapped the page (#307).

#### Fixed

- Fix the Microsoft Store (MSIX) CLI crashing on launch without administrator rights. A Start menu launch runs in `System32`, where the default `./data` directory could only be created elevated.
- Fix the console going blank when selecting the Command Code channel. Its `server_config` provider field is removed (the request now sends an empty config object), and provider forms gain a JSON editor for JSON-typed fields.
- Mark a credential dead only on the refresh errors its upstream client treats as final. Bare 401/403 and shared-client errors are retried, and codes the upstream client logs out on are no longer retried forever. Covers Gemini CLI, Antigravity, Vertex, Grok Build, OpenCode, Cline, Kimi, Kiro, Trae, OrcaTerm, Claude Web, WorkBuddy, Copilot CLI and Codex; Gemini CLI and Antigravity keep a refreshed token when project discovery fails.
- Follow upstream credential lifecycles: Google onboarding waits for a running operation and applies per-tool rules (Gemini CLI never onboards an account that already has a tier; Antigravity onboards free-tier accounts or reports the ineligibility). Kimi and Grok Build retry transient refreshes; Kimi refreshes at half the token lifetime; Grok Build keeps the Team/Organization principal; Cline reads `expiresAt` and requires a refresh token; Kiro rejects expired client registrations locally; WorkBuddy, Trae and OrcaTerm refresh on the upstream schedules.
- Match each upstream client's auth request fingerprint (headers, form/JSON field order, login parameters and user agents) on token, device and identity calls for Google, Codex, Grok Build, Cline, Kimi, OpenCode, Kiro, WorkBuddy, Trae and OrcaTerm.
- Mint Trae's 64-character PKCE verifier, matching the desktop client.
- Fix console admin requests failing on browsers and WebViews without `AbortSignal.any` (before Chrome 116).

#### Changed

- **Breaking:** the Copilot CLI channel now logs in with the Copilot CLI's own OAuth app and sends the GitHub token directly, as Copilot CLI 1.0.77 does; the API origin comes from the account's endpoints. Credentials created through the Copilot Chat app, or holding a minted Copilot token, are refused with a re-login message — log these accounts in again. The SDK `copilot` TLS preset follows CLI 1.0.77.
- The Microsoft Store (MSIX) CLI now defaults its data directory to `%LOCALAPPDATA%\GPROXY` when `--data-dir` / `GPROXY_DATA_DIR` is not set. If you previously ran `gproxy` from a terminal and kept data in that directory's `data` folder, pass `--data-dir <that folder>` or move its contents to `%LOCALAPPDATA%\GPROXY`. Portable ZIP, Linux, macOS and container installs still default to `./data`.
- Refresh container and CI base images (Rust 1.99.1, Node.js 24.22.1), Wrangler 4.151.3 for the Cloudflare deployment, and CI actions.

### 简体中文

#### 新增

- Antigravity 渠道以 Antigravity IDE 身份接入。登录、令牌、Code Assist 初始化和用户信息请求与 IDE 一致（IDE scope、不使用 PKCE、IDE 客户端元数据）；推理、模型目录和配额请求携带 IDE 语言服务器的 User-Agent，模型目录请求会带上项目。SDK 的 `antigravity` TLS 预设改用 IDE User-Agent。
- Android：Android System WebView 低于控制台所需的 111 版本时，启动时给出提示并提供应用商店的更新入口。在旧版 WebView 上，控制台的颜色会变成透明，弹窗与页面内容重叠（#307）。

#### 修复

- 修复 Microsoft Store（MSIX）版 CLI 在没有管理员权限时启动即崩溃的问题。从开始菜单启动时工作目录是 `System32`，默认的 `./data` 目录只有提权后才能创建。
- 修复选择 Command Code 渠道时控制台白屏的问题。移除其 `server_config` 提供商字段（请求改为发送空配置对象），提供商表单新增 JSON 类型字段的编辑控件。
- 仅在上游客户端认定为终态的刷新错误下才将凭证标记为失效。单纯的 401/403 与共享客户端错误会重试，上游会登出的错误码不再无限重试。涵盖 Gemini CLI、Antigravity、Vertex、Grok Build、OpenCode、Cline、Kimi、Kiro、Trae、OrcaTerm、Claude Web、WorkBuddy、Copilot CLI 和 Codex；Gemini CLI 与 Antigravity 在项目发现失败时保留已刷新的令牌。
- 凭证生命周期对齐上游：Google 登录会等待进行中的开通操作，并按工具区分规则（Gemini CLI 不为已有等级的账号开通；Antigravity 为免费等级账号开通，否则报告不符合条件）。Kimi、Grok Build 会重试临时性刷新失败；Kimi 在令牌有效期过半时刷新；Grok Build 保留团队/组织主体；Cline 读取 `expiresAt` 并要求刷新令牌；Kiro 在本地拒绝已过期的客户端注册；WorkBuddy、Trae、OrcaTerm 按上游节奏主动刷新。
- Google、Codex、Grok Build、Cline、Kimi、OpenCode、Kiro、WorkBuddy、Trae 和 OrcaTerm 的令牌、设备码和身份请求在请求头、表单/JSON 字段顺序、登录参数和 User-Agent 上与各自上游客户端保持一致。
- Trae 改为生成与桌面客户端一致的 64 字符 PKCE verifier。
- 修复浏览器或 WebView 不支持 `AbortSignal.any`（Chrome 116 之前）时控制台管理请求失败的问题。

#### 调整

- **破坏性变更：** Copilot CLI 渠道改用 Copilot CLI 自身的 OAuth 应用登录，并像 Copilot CLI 1.0.77 一样直接发送 GitHub 令牌；API 地址取自账号的 endpoints。通过 Copilot Chat 应用创建、或持有换取的 Copilot 令牌的凭证会被拒绝并提示重新登录，请重新登录这些账号。SDK 的 `copilot` TLS 预设同步到 CLI 1.0.77。
- Microsoft Store（MSIX）版 CLI 在未设置 `--data-dir` / `GPROXY_DATA_DIR` 时，默认数据目录改为 `%LOCALAPPDATA%\GPROXY`。如果你之前在终端里某个目录下运行 `gproxy`，数据保存在该目录的 `data` 文件夹中，请通过 `--data-dir <该文件夹>` 指定，或将其内容移动到 `%LOCALAPPDATA%\GPROXY`。便携 ZIP、Linux、macOS 和容器安装仍默认使用 `./data`。
- 更新容器与 CI 基础镜像（Rust 1.99.1、Node.js 24.22.1）、Cloudflare 部署使用的 Wrangler 4.151.3 以及 CI Actions。
