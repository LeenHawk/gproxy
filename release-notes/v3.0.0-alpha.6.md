## v3.0.0-alpha.6

> Follow-up to alpha.5: keep disabled credentials visible without allowing upstream use.

### English

#### Fixed

- Query quota capabilities independently of data-plane credential eligibility. A disabled credential no longer makes the entire admin credential list fail with HTTP 400; disabled credentials remain unavailable for upstream requests.

#### Changed

- Include the Console credential-summary-column removal already committed on the release branch; cycle details remain in the expanded credential view.
- Retain alpha.5's reset-aware quota accounting, ten-minute subscription probes, cycle Token/USD estimates, and per-request usage pages.

#### Breaking Alpha Schema Change

- Earlier alpha databases require a backup and rebuild of the usage and credential-quota statistics tables before deployment. This release does not perform an in-place migration of those old statistics. Preserve credentials, configuration, identities, and billing/admission state.
- Prefer alpha.6 over alpha.5 when deploying the new statistics schema. The separate v2 historical-usage importer is retained.

### 简体中文

#### 修复

- 额度能力查询不再经过数据面的凭证可用性筛选。禁用凭证不会导致整个管理端凭证列表返回 HTTP 400，同时仍禁止它用于上游请求。

#### 变更

- 包含当前发布分支已提交的凭证额度摘要列移除调整；周期详情仍保留在凭证展开区域。
- 保留 alpha.5 的重置周期识别、按发送时间记账、十分钟订阅探测、周期 Token/USD 估算和逐次用量页。

#### Alpha 数据结构不兼容变更

- 旧 alpha 数据库上线前必须备份并重建用量及凭证额度统计表，不提供这些旧统计的原地迁移。凭证、配置、身份和计费准入状态应保留。
- 新统计结构请使用 alpha.6，而非 alpha.5；独立的 v2 历史用量导入仍保留。
