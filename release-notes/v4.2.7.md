## v4.2.7

> System prompts sent to GPT-6.2 through a conversion or the Codex channel are cached again. This release also keeps idle AI Studio Playground sessions alive, imports several Playground sessions at once, and signs the HarmonyOS application.
>
> 经协议转换或 Codex 渠道发往 GPT-6.2 的系统提示重新可以命中缓存。本次还会让空闲的 AI Studio Playground 会话保持有效，支持一次导入多个 Playground 会话，并为 HarmonyOS 应用签名。

### English

#### Prompt caching on GPT-6.2

Models starting with GPT-6.2 place the Responses `instructions` field after `input`, outside the cached prefix, and bill it at the uncached input rate on every request. OpenAI's guidance is to send reusable instructions as a developer message at the start of `input`.

- Claude and Gemini requests converted to Responses carry the system prompt as a leading developer message instead of `instructions`.
- The Codex channel moves `instructions` into a leading developer message, the way the CLI sends its base instructions, and turns system messages into developer messages where they stand. It used to merge system messages into `instructions`.
- With the OpenAI magic cache strings enabled, a string in `instructions` moves the text into the marked developer message. The marker used to sit on an empty message in front of `input`.
- Requests sent natively to the OpenAI channel are not changed; `instructions` is forwarded as the client sent it.

#### Channels

- AI Studio Playground rotates idle sessions on a timer. Credentials were refreshed only when a request used them, so an unused session expired. The rotation period follows Google's reply, ten minutes by default.
- AI Studio Playground accepts `googleSearchRetrieval`, `googleSearch.searchTypes` (web search, image search or both), the `HARM_CATEGORY_CIVIC_INTEGRITY` category, and fields under their proto names such as `google_search`, `function_declarations` and `system_instruction`.
- AI Studio Playground no longer fails a generation on the element without content that Google now appends to a GenerateContent stream.
- A request a channel cannot express is answered with 400 instead of 500, and an unsupported tool is named in the error.
- Codex supports workspace discovery as of CLI 0.171.0.
- Claude Code OAuth login and refresh are aligned with CLI 2.1.329.

#### Console

- The bulk import for Playground accepts several cookie sessions at once: exports pasted one after another, an array of exports or of secret objects, or one Cookie header per line.
- The Playground import tells you to open google.com before exporting cookies. Without that visit the export lacks the rotating session cookies, and rotation fails with 401.

#### Packages

- The ARM64 HarmonyOS application is signed. HarmonyOS command-line packages and the x86_64 HarmonyOS application are no longer published.
- The Node.js container image for the serverless binary is removed. Render and Heroku already run the release image; Vercel and Netlify are not affected.

### 简体中文

#### GPT-6.2 的提示缓存

从 GPT-6.2 起，模型把 Responses 的 `instructions` 字段放在 `input` 之后，不在可缓存前缀内，每次请求都按未缓存输入价计费。OpenAI 的建议是把可复用的指令作为 `input` 开头的 developer 消息发送。

- Claude 和 Gemini 请求转换为 Responses 时，系统提示作为开头的 developer 消息发送，不再写入 `instructions`。
- Codex 渠道把 `instructions` 移入开头的 developer 消息，与 CLI 发送基础指令的方式一致，并把 system 消息原地改为 developer 消息。此前它会把 system 消息合并进 `instructions`。
- 启用 OpenAI 魔法缓存字符串时，`instructions` 中的字符串会把文本移入带标记的 developer 消息。此前标记落在 `input` 前面的一条空消息上。
- 原生发往 OpenAI 渠道的请求不变，`instructions` 按客户端发送的原样转发。

#### 渠道

- AI Studio Playground 定时轮换空闲会话。此前凭证只在有请求使用时才刷新，闲置的会话会过期。轮换周期跟随 Google 的应答，默认十分钟。
- AI Studio Playground 接受 `googleSearchRetrieval`、`googleSearch.searchTypes`（网页搜索、图片搜索或两者）、`HARM_CATEGORY_CIVIC_INTEGRITY` 类别，以及 `google_search`、`function_declarations`、`system_instruction` 等 proto 字段名。
- Google 现在会在 GenerateContent 流末尾追加一个不含内容的元素，AI Studio Playground 不再因此生成失败。
- 渠道无法表达的请求返回 400 而不是 500，错误信息会指出不支持的工具。
- Codex 支持 CLI 0.171.0 的工作区发现。
- Claude Code 的 OAuth 登录与刷新对齐到 CLI 2.1.329。

#### 控制台

- Playground 批量导入支持一次导入多个 Cookie 会话：连续粘贴的多份导出、导出或密钥对象的数组，或每行一个 Cookie 头。
- Playground 导入会提示先打开 google.com 再导出 Cookie。不访问的话导出里缺少轮换用的会话 Cookie，轮换会返回 401。

#### 安装包

- ARM64 HarmonyOS 应用已签名。不再发布 HarmonyOS 命令行包和 x86_64 HarmonyOS 应用。
- 移除了无服务器二进制的 Node.js 容器镜像。Render 和 Heroku 已在使用发布镜像；Vercel 和 Netlify 不受影响。
