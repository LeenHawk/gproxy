## v4.3.1

> Channel refusals of malformed requests are answered with 400 and their own message instead of a 5xx or a configuration error. Kiro gains login variants, reasoning effort and signed reasoning replay; Devin sends forced `tool_choice` upstream. The console edits model routes in place and shows the publisher's announcements on the landing page, and the Cloudflare, Netlify and Vercel deploy buttons are back.
>
> 渠道拒绝格式错误的请求时，返回 400 和渠道自己的错误信息，不再返回 5xx 或配置错误。Kiro 支持登录方式选择、推理强度和带签名推理的回放；Devin 会把强制的 `tool_choice` 发往上游。控制台可以就地编辑模型路由，首页会显示发布者的公告；Cloudflare、Netlify 和 Vercel 的一键部署按钮恢复可用。

### English

#### Errors

- A request a channel refuses for its own content (body shape, a missing or unknown model, unsupported fields, tool and content checks) is answered with 400 `invalid_request` and the channel's message. It used to read "invalid channel configuration", and for Devin, Claude Web and AI Studio Playground it was a 5xx that counted as a failed attempt.
- System clock and OS randomness failures are reported as host errors (500) instead of a provider configuration error.
- Kiro client registration that AWS OIDC refuses returns the portal's status and body.

#### Channels

- Kiro offers a choice of login: GitHub or Google for the device login, AWS Builder ID or an Identity Center portal for the authorization code. The console's login dialog and the setup wizard list the choices. A login without a choice still follows the provider's `login_provider`.
- Kiro sends a Responses `reasoning.effort` upstream: Claude 4.6 and later get adaptive thinking with that effort, GPT-5.6 gets `reasoning.effort`. Levels a model does not offer are clamped; Claude 4.5 and older, and `auto`, are sent as before.
- Kiro keeps the upstream's reasoning signature in `encrypted_content` and replays signed reasoning in later turns. Reasoning without a Kiro signature is dropped; it used to fail the request.
- Kiro lists models through the Kiro control plane and is aligned with kiro-cli 3.7.0, including its TLS fingerprint.
- Devin sends `tool_choice` upstream: `required` (and Anthropic `any`) and a named function force a tool call, `none` drops the tools. It used to refuse forced tool choice.
- Devin is aligned with CLI 3000.15.14. A configured fingerprint of the older length is still sent as it is.
- Devin and Kiro accept gzip responses by default, as both CLIs do. An explicit connection profile still replaces the default.
- Devin, Cline, Copilot CLI and Factory answer an OpenAI client's `GET /v1/models`. The lite engine used to answer 501. Devin's model list names xAI, DeepSeek and NVIDIA as owners where it used to leave them blank.
- AI Studio Playground accepts the benefit tier reply of free accounts. Every refresh of a free account used to fail with "missing benefit tier".
- Antigravity is aligned with CLI 1.5.18, hub 2.35.2 and IDE 2.9.0. Agent calls carry a session id derived from the conversation, as the CLI now sends.
- Claude Code is aligned with CLI 2.1.332.
- Codex is aligned with CLI 0.172.0. A 429 for an exceeded API key spend limit is no longer retried.

#### Console

- Model routes are edited in place. Each route is a card that lists its members by tier and opens into an editor; the route and its members are saved together. Members can be switched off, moved between tiers or removed, and weighted routes show each member's share.
- The landing page shows the publisher's announcements to operators who may open the update page. Each can be closed.
- Each row on the credential usage page has a refresh button that queries the credential's quota from the upstream.
- An accounts.google.com cookie export pasted next to a Playground session is merged into that session instead of failing as another account.
- The quota reset dialog and the new model button work over plain HTTP. They used to fail outside HTTPS and localhost.

#### Packages

- The Cloudflare, Netlify and Vercel deploy buttons are back. Every release publishes `gproxy-lite.zip`, and the templates download it at build time, so a deploy needs no Rust toolchain.
- The HarmonyOS AppGallery package is built and uploaded to AppGallery Connect with each stable release.

### 简体中文

#### 错误

- 渠道因请求内容拒绝的请求（请求体结构、缺少或未知的模型、不支持的字段、工具和内容检查）返回 400 `invalid_request`，并附上渠道的错误信息。此前显示的是"渠道配置无效"；Devin、Claude Web 和 AI Studio Playground 还会返回 5xx，并把这次尝试计为失败。
- 系统时钟和操作系统随机数故障报告为主机错误（500），不再报告为提供商配置错误。
- Kiro 客户端注册被 AWS OIDC 拒绝时，返回门户的状态码和响应体。

#### 渠道

- Kiro 可以选择登录方式：设备登录可选 GitHub 或 Google，授权码登录可选 AWS Builder ID 或 Identity Center 门户。控制台的登录对话框和初始化向导会列出这些选项。不选时仍按提供商的 `login_provider` 登录。
- Kiro 会把 Responses 的 `reasoning.effort` 发往上游：Claude 4.6 及以后的模型使用该强度的自适应思考，GPT-5.6 使用 `reasoning.effort`。模型不支持的强度会就近取值；Claude 4.5 及更早的模型和 `auto` 照旧发送。
- Kiro 把上游的推理签名保存在 `encrypted_content` 中，并在之后的轮次回放带签名的推理。没有 Kiro 签名的推理会被丢弃，此前会导致请求失败。
- Kiro 改为通过 Kiro 控制面列出模型，并对齐到 kiro-cli 3.7.0，包括 TLS 指纹。
- Devin 会把 `tool_choice` 发往上游：`required`（以及 Anthropic 的 `any`）和指定函数会强制调用工具，`none` 会去掉工具。此前强制工具选择会被拒绝。
- Devin 对齐到 CLI 3000.15.14。已配置的旧长度指纹仍按原样发送。
- Devin 和 Kiro 默认接受 gzip 响应，与两个 CLI 一致。显式配置的连接配置仍会替换默认值。
- Devin、Cline、Copilot CLI 和 Factory 会响应 OpenAI 客户端的 `GET /v1/models`，此前 lite 引擎返回 501。Devin 的模型列表会把 xAI、DeepSeek 和 NVIDIA 标为所有者，此前这几项为空。
- AI Studio Playground 接受免费账号的权益等级应答。此前免费账号每次刷新都会以"missing benefit tier"失败。
- Antigravity 对齐到 CLI 1.5.18、hub 2.35.2 和 IDE 2.9.0。Agent 调用会带上由会话派生的 session id，与 CLI 现在的行为一致。
- Claude Code 对齐到 CLI 2.1.332。
- Codex 对齐到 CLI 0.172.0。API Key 消费上限超额导致的 429 不再重试。

#### 控制台

- 模型路由可以就地编辑。每条路由显示为一张卡片，按层级列出成员，展开后即为编辑器；路由和成员一起保存。成员可以停用、在层级间移动或删除，加权路由会显示每个成员的占比。
- 首页会向有权限打开更新页的管理员显示发布者的公告，每条都可以关闭。
- 凭证用量页的每一行都有刷新按钮，可以向上游实时查询该凭证的配额。
- 在 Playground 会话旁粘贴的 accounts.google.com Cookie 导出会合并进该会话，不再被当成另一个账号而失败。
- 配额重置对话框和新增模型按钮可以在普通 HTTP 下使用。此前在 HTTPS 和 localhost 之外会出错。

#### 软件包

- Cloudflare、Netlify 和 Vercel 的一键部署按钮恢复可用。每次发布都会附带 `gproxy-lite.zip`，模板在构建时下载它，部署时不需要 Rust 工具链。
- 每个正式版都会构建 HarmonyOS AppGallery 安装包，并上传到 AppGallery Connect。
